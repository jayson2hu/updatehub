# 内容管理员操作指南

本轮更新：2026-09-26。适用于运营工作台、软件与版本公告、指南、常见问题和合集管理。

主要工作是维护公告：先说清楚发生了什么、影响谁和建议采取的行动，再提供版本、注意事项与官方来源。软件档案用于补充背景与官方入口，不应代替公告正文。

## 首次登录

管理员由运维显式运行 `python -m app.cli create-admin` 创建，邮箱与密码来自 `ADMIN_INITIAL_EMAIL`、`ADMIN_INITIAL_PASSWORD`。没有默认账号。打开 `/admin`，使用已创建的账号登录；完成维护后退出，尤其是在共享电脑上。

初始密码只用于创建账号，创建后由运维清除环境配置。当前没有自助找回密码、二次验证和普通用户注册。

## 从运营工作台开始

登录后进入 `/admin`“运营工作台”。公告仍是主要发布入口；左侧分别提供公告管理、软件管理、指南管理、常见问题、合集管理、分类管理和操作日志。手机上先显示工作台、公告和软件，点击“指南、问题与更多管理”展开其余栏目。

- “待处理发布”列出待审核或草稿公告，以及草稿、已下线的指南、问题和合集。点击标题继续处理；页面底部还可按内容类型查看待发布列表。
- “软件内容缺口”检查已公开软件是否缺少官方入口、版本依据、指南或常见问题。每个缺口都有直接操作入口；从这里新建指南或问题时，软件关联会预填。默认展示前 6 款，使用“再查看…”展开其余结果。
- “用户在找什么”可切换近 7、30、90 天，查看实际搜索次数、无结果搜索次数、官方入口点击次数。无结果词可用于检查软件别名、用途或缺少的解答；含敏感信息的搜索词会隐藏。
- “官方入口点击”按软件聚合，也可展开查看具体入口。点击软件名称可维护资料；点击量不是下载完成量、活跃人数或质量评分，同一用户重复操作也会计数。

页面没有记录时会说明暂无数据，不会生成演示统计。统计读取失败时使用“重新加载工作台”；上方新建公告、添加软件、编写指南、回答问题、整理合集仍可继续使用。

## 编写指南

进入“指南管理”，点击“新建指南”。填写标题与简介，再填写正文、操作步骤，或同时使用两者。发布前需要简介，以及正文或至少一个完整步骤。

点击“添加步骤”后，每一步分别填写“步骤标题”和“操作说明”。上下箭头调整顺序，移除按钮删除当前草稿中的这一步。最多 30 步；尚未写完的步骤可以保存草稿，发布前每个已添加步骤都必须填写完整。

“展示范围”可关联一款软件、选择分类及适用平台。软件关联可留空以编写通用指南；关联软件在发布前必须公开。正文使用普通文字分段即可，系统保留段落，不会把输入当作可执行网页代码。

## 回答常见问题

进入“常见问题”，点击“添加问题”。“问题”使用用户实际会问的表述，“详细解答”先回答结论，再说明原因、操作方法和适用条件。“简短回答”可选；仅填写问题与详细解答也可发布。

可以关联软件、分类和平台。相同问题不必按不同入口重复创建；先查找已有问题，判断是否应完善现有解答。需要修改已发布问题时，按下方内容生命周期操作。

## 整理软件合集

进入“合集管理”，点击“新建合集”。填写合集名称与“适合什么需求”；在“适用用途”中用逗号分隔用户熟悉的场景，例如“开始写作，远程协作”。这些用途会成为新手入口的用途选项。“选择与使用说明”可解释软件之间如何搭配。合集通过下方的有序成员关联软件，不使用单软件关联字段。

1. 在“合集中的软件”里输入名称缩小范围，选择软件并点击“加入合集”。不能重复加入同一软件，最多 100 款。
2. 为每款软件选择“必备、推荐、可选”，填写“选择理由 / 使用提示”。这些说明用于帮助用户判断是否需要这款软件。
3. 使用上下箭头调整展示顺序。移动后，软件对应的理由与推荐程度会一起移动。
4. 发布前至少包含一款软件，且选中的所有成员都必须公开。遇到未公开成员，可另开其软件资料页处理，返回后点击“重新检查软件状态”。

若成员后来下线，该成员会从公开合集隐藏；全部成员都下线时，合集也不再公开可见。演示软件加入合集时会自动带出演示标记，不能通过清除标记把演示内容作为真实建议发布。

## 指南、问题和合集的保存与发布

这三类内容使用统一流程：

1. “保存草稿”提交当前内容，访客看不到草稿。“预览内容”只查看当前效果，也可能包含尚未保存的修改。
2. “保存并预览”先保存，再进入确认窗口。若缺少发布必填项，错误列表可点击定位到具体字段；修正后再次操作。
3. 在预览中核对文字、步骤、关联软件、合集顺序和演示标记，再点击“确认发布指南”“确认发布常见问题”或“确认发布合集”。成功后可打开“查看公开页面”核对。
4. 已发布内容以只读方式显示。需要修改时点击“下线后编辑”，再“确认下线并编辑”。此时公开内容暂时隐藏，回到草稿；修改后重新保存、预览、确认发布。
5. 不再使用的内容可“归档”。记录仍会保留，之后可以“恢复为草稿”；恢复不会自动公开。

指南、问题和合集没有公告的“待审核”状态，也不会像已发布公告那样直接保存公开文案修改。已分享的网址标识尽量保持不变，自动生成的标识通常无需手动填写。

保存失败时，当前输入会保留，阅读错误原因后可重试。离开未保存的编辑器时会提示；当前标签页还会临时保留草稿，返回编辑器时显示“已恢复尚未保存的内容”。服务器记录已变化时不会套用旧临时稿；浏览器临时保存不能代替“保存草稿”，明确选择放弃修改会清除这份暂存。

## 写一条可执行的公告

发布软件版本时，先从“软件管理”找到软件，点击“版本管理”。该页面区分“发布新版本”与“补录历史版本”，并保留草稿、已发布和归档记录。软件的当前版本由版本公告维护，编辑软件名称或官方入口不会创建版本历史。

“发布新版本”会预填关联软件与上一版本；填写本次版本、来源、变化和建议，点击“保存并预览”，核对后再“确认发布公告”。“保存草稿”只保存内容。发布成功后可直接查看公开公告、复制通知或返回这款软件的版本管理。

“补录历史版本”只补齐以前的记录，必须填写实际官方发布日期。它不会替换当前版本、当前建议或当前公告，也不会进入默认最新公告与关注列表；访客可从版本历史或“包含历史版本记录”筛选中查看。复制历史内容时，通知会明确标注它不是当前更新建议。

网址标识会自动生成，无需填写英文。高级设置允许维护标识，已经分享的公开地址应保持稳定。未保存时点击其他站内入口会提示；同一标签页可恢复与当前服务器记录一致的临时草稿。临时恢复不等同于保存，仍需点击保存将内容提交到后台。

1. 选择类型：版本更新、使用提醒或维护通知。站点通用提醒可以不关联软件；版本更新必须关联已公开的软件。
2. 标题写清对象和事件；摘要概括结论，不只写“有更新”。正文解释变化与背景。
3. 填写影响范围和建议行动，说明哪些用户需要处理、哪些用户可以等待。把兼容性、已知问题与操作前注意事项写在相应位置。
4. 版本更新填写新版本、旧版本（如已知）、官方发布日期与官方版本说明地址。版本号与日期应与来源一致，不能用公告录入日期冒充厂商发布日期。
5. 演示内容保持演示标记。演示版本、升级建议和维护安排不能作为真实新闻发布，也不能更新真实软件的当前确认版本。

## 草稿、审核、发布与归档

保存草稿用于继续整理，不会公开。预览核对的是公告展示效果，不能代替核实内容。可以先提交审核，也可在草稿核对完成后直接通过独立的发布操作进行人工确认；普通保存不会公开。当前所有管理员使用同一权限体系，审核是可选整理阶段，不表示已经实现双人审批。

发布前至少核对标题、摘要、正文、影响范围和行动建议。版本更新还要确认关联软件已公开、版本完整、官方来源有效。系统校验不通过时，先修正内容再发布；不能通过清空字段、部分保存或直接修改状态绕过检查。

已发布公告可以修正文案，但保存时仍会重新检查完整发布条件。修改旧公告不应将其显示为新发布；历史记录的首次发布时间与最后修改时间承担不同作用。若公告不再适合公开，使用归档，后台会保留内容与审计。

草稿、审核中、归档公告不会出现在公开列表、详情、软件关联公告或关注内容中。关联软件下线后，公告的公开入口也会隐藏；站点通用通知仍可独立展示。

置顶用于让仍需关注的公告优先显示，不代表公告刚刚发布。完成事项应及时取消置顶或归档，避免占用读者注意力。

## 复制群通知

在已发布且当前可公开查看的公告中选择纯文本或 Markdown 文案，执行复制，再由管理员粘贴到实际群聊。复制前核对标题、影响、行动、详情地址和演示标识，复制成功提示应与剪贴板结果一致。

本站不会自动向群聊发送消息。草稿、审核中、归档或关联软件已下线的公告不能生成面向公开读者的通知。正文修改后重新获取文案，避免继续传播旧内容。

## 维护软件

1. 新建软件，先填写名称、一句话简介和官方网站，点击“保存软件并管理版本”。官网会在未单独配置入口时自动作为官方来源；详细介绍与分类可继续补充。网址标识自动生成，发布后尽量保持稳定。
2. 添加常见别名、中文称呼、用途、标签和支持平台，帮助用户在不知道准确名字时搜索。避免无关关键词。
3. 上传有授权的 PNG、JPEG 或 WebP 图标，单文件最多 2 MB，尺寸不超过 2048 × 2048。系统会缩至 512 × 512 以内并重新保存为 PNG。SVG 和软件安装包不支持上传。
4. 填写官网、文档或项目源代码地址，再维护官方链接列表：名称、类型、平台、架构、主入口与启用状态。
5. 检查说明与来源后发布。未发布软件不会出现在公开列表、详情和跳转接口。

使用下线操作会保留后台记录，同时从公开目录隐藏并停止对应官方跳转。重新编辑后可以再次发布。删除分类前先将引用该分类的软件迁移到其他分类，否则系统拒绝删除。

## 官方来源与版本说明

添加链接前人工核对域名和页面内容。系统只能检查 URL 格式与地址边界，无法证明网站确为官方。优先填写厂商官网、厂商明确链接的应用商店与官方项目仓库，不填写网盘、未知下载站或短链接。

主入口用于帮助用户选择首要来源；其他入口标清平台与架构。失效或无法确认的入口先禁用，再排查。当前没有自动网址巡检；`last_checked_at` 不能被理解为持续监控结果。

版本号、更新建议和更新原因由管理员填写，不会自动查询厂商。种子软件和公告带演示标记，演示版本不能用作“当前最新版本”的公告。软件资料可在核实来源并更新完整内容后调整演示状态；已发布公告的演示标记固定，应新建真实公告发布已核实信息。

软件详情优先展示当前版本与建议，再展示关联公告、版本历史和资料。补录旧版本必须使用“补录历史版本”，并填写真实官方发布日期；补录模式会独立保护当前记录，不依赖版本号或同一天内的录入顺序。普通版本公告未填写官方日期时使用首次发布的 UTC 日期，系统不会从任意格式的版本号推断新旧。

首次发布后，公告类型、关联软件、官方发布日期、演示标记和历史补录属性不能再改，需修正这些字段时应新建准确公告。归档不会回退软件当前版本，也不会让较旧公告重新取得版本同步资格。演示公告不能覆盖真实软件资料；真实公告可以将软件从演示资料更新为真实记录。当前版本公告归档后不再提供公开跳转，软件仍保留已记录的版本事实。

## 日常检查

- 发布后从公告中心打开详情，确认“发生了什么、影响谁、怎么处理”和官方来源完整；再检查软件关联公告与关注列表。
- 检查类型、重要程度、软件筛选及置顶顺序，确认草稿、审核与归档没有公开泄露。
- 检查每个官方入口的可见域名与最终落地页，确认“下载”文字确实指向对应官方位置。
- 用手机宽度检查名称、说明、图标和按钮。
- 在审计记录中复核管理动作。审计仅供追踪，当前没有一键撤销功能。

正常情况下，“关注”保存在访客当前浏览器，清理浏览器数据后会丢失。浏览器禁止写入时会明确提示只能临时保留，并真实使用临时清单。关注页显示所选软件的公开公告，默认不含历史补录；它不提供邮件、推送、账号同步或主动通知。
