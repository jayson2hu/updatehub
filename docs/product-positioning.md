# 产品定位调整：以公告为核心

更新时间：2026-09-22。依据用户最新反馈“这个产品给的是公告，重新定位下这个产品”，本文件覆盖原实施计划中“软件发现 / 软件导航优先”的信息层级。原始需求文档保留作为历史依据。

## 一句话定位

面向固定用户群的软件公告中心：管理员统一发布软件更新、使用提醒和维护通知，用户快速知道发生了什么、是否影响自己、接下来应该做什么。

## 用户首先要解决的事情

1. 看最新公告，避免漏掉重要变化。
2. 判断公告是否涉及自己使用的软件或平台。
3. 理解建议采取的行动、原因和注意事项。
4. 必要时进入关联软件的官方渠道。

软件资料、用途搜索和官方地址承担公告背景与行动入口的职责。首页首先提供公告，不再以软件推荐和软件搜索作为主视觉。

## 内容与发布

- 版本更新：新旧版本、主要变化、升级建议、影响用户、已知问题、官方来源。
- 使用提醒：需要注意的配置、兼容性与操作事项。
- 维护通知：维护安排、影响范围、恢复或后续说明。

每条公告至少有标题、摘要、类型、正文、影响范围、行动建议。软件可关联，站点通用通知可以不关联。版本更新发布必须关联已公开软件并填写版本；官方 URL 必须通过安全校验。发布保留人工确认。

状态：草稿 → 可选待审核 → 人工确认发布 → 已归档。管理员可先保存为待审核，也可在草稿核对完成后通过独立发布操作确认；普通保存不能直接公开。后台提供预览、人工发布、修改、归档和复制群通知。公告更新、软件版本变化、审计记录须在同一事务完成。历史公告修改不能覆盖较新公告决定的当前版本。

## 新的信息层级

首页 / 公告中心：简洁说明与公告搜索 → 置顶公告 → 最新公告列表 → 软件 / 类型 / 重要程度筛选。辅助侧栏显示公告阅读说明、关注清单与软件档案入口。

公告详情：结论与影响 → 建议行动 → 具体变化 → 注意事项和来源 → 关联软件 / 官方入口。软件详情增加关联公告记录。

软件详情先展示当前版本、当前建议与官方入口，再提供相关公告、版本历史和资料栏目。公告详情提前展示来源、关注和复制入口；旧公告在正文前明确提示“当时的建议”，并在当前版本公告公开时提供直接返回入口。

版本历史线：公告详情和软件档案直接展示该软件已公开的版本公告。按官方发布日期倒序排列，缺失时以首次站内发布的 UTC 日期为准，同日期再按首次发布时间排序；置顶和后续修改不改变历史顺序。每条记录展示版本、日期、主要变化、当时的更新建议和完整公告入口，历史较长时分页浏览。

“正在阅读”标记与“档案当前版本”分别展示，查看旧公告时仍能辨认当前记录。草稿、归档、使用提醒和维护通知不作为版本节点；仅填写上一版本号不会自动生成一条历史公告。归档当前版本公告后保留软件档案已记录的版本事实，不暴露被归档内容。

后台从软件进入版本管理，分别提供“发布新版本”和“补录历史版本”。补录必须填写实际官方日期，持久化为历史记录，永不替换当前版本、建议或来源指针。默认公告流和关注流排除补录，读者可主动选择包含历史；补录的分享文案明确标明非当前建议。软件资料编辑只维护资料，版本事实由版本发布流程维护。

“我的关注”以所关注软件的公告为主要内容，保留软件清单用于管理关注关系。软件库保持完整功能，降为辅助导航。

## 2026-09-26 补齐辅助任务

公告主线保持不变。新增帮助中心、可搜索和分类的FAQ、分步骤指南、场景软件合集、按描述/用途查找和三步新手关注流程；这些内容连接到软件档案的当前版本与官方入口。首页以紧凑的新手入口和侧栏任务链接提供发现路径，不改变公告第一顺位。

后台工作台从“维护内容和处理缺口”组织，提供待发布内容、软件资料缺口、经过过滤的搜索关键词与无结果计数、官方入口点击汇总。所有指南/FAQ/合集都有独立内容管理、草稿、预览、人工发布和下线。统计仅代表操作次数，不能解释为独立用户、问题解决率或真实推荐成功率。

详见 `product-experience-design.md`。

## 公告轮次交付范围（历史）

新增公告模型与迁移、公告公开接口、后台草稿 / 审核 / 发布 / 修改 / 归档、群通知复制、公告列表与详情，重做首页信息层级，接入关注筛选和软件关联公告。沿用原有认证、CSRF、审计、官方跳转、演示数据标注及手机适配。

不自动生成真实新闻或声称已经核实官方当前版本。演示公告明确标记，包含的版本和建议不能当作官方事实。

## 成功标准

- 用户进入首页立即知道近期有哪些公告，而非先寻找软件。
- 一条公告能回答“发生了什么 / 与谁有关 / 我该怎么做”。
- 管理员在后台发布后，公开公告、软件当前版本和群通知保持一致。
- 公告下线、草稿和归档不在公开入口泄露；管理员可查看历史与审计。
