# ADR-0007：中文搜索输入与独立微信引导

日期：2026-10-19。依据 R-GLOBAL-03、R-GLOBAL-06、R-ADMIN-12。

## 问题

桌面导航原先在每次 input 事件中跳转搜索页，中文输入法的候选拼音也可能触发导航，打断选字。搜索页在长时间组合输入时也可能把未确认的拼音写入搜索统计。

原 `inapp_hint` 同时控制微信和小红书的提示条，默认开启，导致微信默认出现「无法直接下载」；与此同时下载按钮只在小红书中拦截，提示与按钮行为不一致。

## 决定

1. 导航在 `compositionstart` 到 `compositionend` 期间保留输入，确认中文后再交给搜索页。普通非组合输入仍按需求即时进入搜索。搜索页组合期间不更新 URL、不上报搜索词，确认后恢复防抖及上报；选字回车不导致搜索框失焦。
2. 保留 `inapp_hint` 原有的小红书提示条开关。新增 `wechat_inapp_hint`，默认 false，由后台单独配置。微信默认不显示提示条、不拦截官方链接；管理员确认存在限制后开启，同步显示提示与下载引导。
3. 小红书下载按钮仍提供手动打开引导，不依赖自动唤起浏览器。关闭小红书提示条不会取消按钮处的手动兜底。
4. 新提交的站名由服务端校验至少 2 字，继续保留中文最多 8 字、英文最多 16 字的上限。旧版已保存的单字站名仍可读取，也可独立修改其他设置，避免升级后公开页面报错；显式修改站名时须满足新规则。无效保存不修改现有设置。

## 迁移与兼容

`e4719f0c2b86` 在 `station_settings` 增加非空布尔列 `wechat_inapp_hint`，服务器默认 false。已有站点自动保持微信直达行为，不更改小红书开关、软件或版本；新字段仅增不减。旧客户端可忽略该字段，两端小程序不显示这些 Web 宿主提示。

迁移前保留 SQLite 与图片、开发签名密钥备份。降级只删除新增开关列，会丢失该选项的设置；回滚后如再次升级，默认关闭。

## 验证边界

API 回归覆盖独立开关、数据库会话重新读取、默认值、无效站名与保存失败后的原值。统一迁移回归覆盖 SQLite 升降级与模型对齐、PostgreSQL 离线 SQL。

浏览器已实际执行拼音组合、确认中文、焦点交接及两宿主开关检查，记录于 `artifacts/acceptance-20261019/browser-full/report.json`。组合输入通过 composition 事件模拟，宿主通过 UA 模拟；不代表真机输入法候选窗、真实微信/小红书或 Safari 已验收。本机原生 PostgreSQL 17 迁移也已执行升/降/升，见统一验收记录。
