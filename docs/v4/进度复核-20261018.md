## 需要处理的问题

### 1. 新版后台尚未形成发布闭环

软件编辑器虽增加了新字段默认值，但没有分类、开发者、标签、按设备安装指南等表单；版本编辑器没有四档更新建议、稳定版选择、结构化更新内容等表单。新工作台、反馈处理、想要的软件处理、广告分位置控制与统计、扩展站点设置仍未接入。

结果：前台已经展示新能力，管理员仍无法通过当前后台完整维护。应先完成 M4，再验收“发布 → 前台/小程序同步 → 复制群通知”的完整任务。

### 2. 同步码存在两个已复现的问题

- 重新生成同步码后，旧码仍可恢复，接口返回 200，与“重新生成（旧码作废）”不符。`SyncService.create` 只新增记录，客户端也未传递要替代的旧码。
- Web 只用收藏数量判断缓存是否仍有效：收藏 A 生成码，改为只收藏 B，再点击生成，仍复用 A 的码；恢复后得到已经取消的 A。`sheets.tsx` 中 `saved.count === favorites.length` 不足以判断收藏内容是否变化。

这两项分别有接口与真实页面复现记录。建议按收藏内容和常用设备校验缓存，并补齐旧码撤销规则及回归测试。需求还要求哈希保存同步码；当前模型以原始 `code` 为主键，需要与实际实现统一。

### 3. 反馈改投、撤销与来源未闭环

Web 已投票后直接阻止再次反馈；小程序的撤销只删除本机记录，没有撤销服务端计数，改投会继续累加另一项。后端提交接口只有累加逻辑，未达到需求中“改投后一减一加”的规则。此外缺少反馈来源字段，后台无法区分 Web、微信和小红书。

“想要的软件”也只保留提交时的本机状态，后台收录后没有公开查询接口来更新用户看到的状态；属于仍需衔接的流程。

### 4. 演示内容与真实获取入口混淆

数据库内的软件均标为示例，但新版详情没有显示明显示例标识。`yunpan.example.com` 等占位地址被展示为“官方下载”“下载稳定版”。本次实际页面确认：`is_demo=true`、目标为示例域名、页面没有“示例”文字。

广告总开关当前也已开启，正在展示走查用广告素材。正式交付前应恢复明确的演示状态、移除占位获取入口，并根据站主的真实配置决定是否启用广告。没有真实链接时应显示“暂未配置获取链接”。

### 5. 手机首屏仍未满足内容优先目标

390×844 下，第一张更新卡从 y≈760 开始，到 y≈894 结束；底部导航从 y=783 开始，因此首屏没有一条完整更新。大块概览、公告与两行分类占用了主要空间。

建议优先缩短概览区，把分类改成紧凑入口或横向一行，让公告和至少一条完整更新进入首屏。当前页面没有横向溢出，但“无溢出”不等于首次访问效率已达标。

### 6. 旧开发服务异常与上线前验收

原来的 3010 开发服务在软件详情返回 500，日志出现 worker 异常和 EPIPE。独立正式构建启动于 3011 后，9 款详情全部正常，33 项走查无脚本错误；目前证据说明错误只在旧开发服务复现，不能据此认定详情源码整体不可用。

可用预览：`http://localhost:3011/`。旧开发服务应单独重启检查。两平台真实 AppID、HTTPS 服务、开发工具编译与真机验收仍需完成；本次没有将 Node 逻辑测试记作原生验收。
