## 本轮修复

- 反馈使用 `/station/feedback/vote`，保存签名凭据。点有问题即时计票；补说明只改明细。来源从构建平台传入。
- 「想要的软件」保存原请求 ID，合并后查询目标状态但不覆盖原 ID，避免后续无法匹配本机记录。关联上架软件后显示入口。
- 同步码清洗/格式为 10 位、展示 5+5，30 天有效。重新生成旧码失效；缓存指纹含完整收藏 ID 与常用设备，同数量换收藏不会复用旧码。
- 安装配图、提示、收费、收录时间和版本/公告浏览计数使用新持久字段。
- 稳定版主入口的大小、系统要求、安装提醒均取稳定版；指定稳定版缺链接时显示「查看稳定版入口」，不退回复制问题版。仍要当前版的次入口保留独立提取码；最新版为 hold 时，旧版提示不催促升级。
- 广告仅面积 50% 且持续 1 秒曝光；无观察能力不计，关闭/失败清理计时。
- 复制被拒时展示完整可选择文本，网络失败保留重试；写请求不读缓存，成功使内容缓存失效。

## 配置与待验

配置示例 `.env.miniprogram.example`：公开 AppID、`MINIAPP_API_BASE`（含 `/api/v1`）、`MINIAPP_WEBSITE_BASE`。不放 AppSecret。正式 API 必须配置真实 `PUBLIC_SITE_URL`、合法域名和精确 `MINIAPP_REFERER_PREFIXES`；不能根据本地无 Origin 调试成功推断生产可用。

完整导入、构建、存储结构、事件和两端真机清单见 [小程序手册](../station-miniprograms.md)。验收重点：

1. 两端原生编译全部七页面与组件，原生底栏、安全区、吸顶和键盘。
2. 真实设备复制/拒绝权限兜底、稳定版/旧版对应地址，分享卡直达同一设备和版本。
3. 网站与两端互相恢复同步码，后台处理请求后返回页面可见结果。
4. 有问题/改投/撤销/补说明，后台来源与计数一致；真机广告观察能力符合口径。
5. HTTPS 网络、合法域名、原生 Referer 与线上来源校验；启动、重启及离线重试。

本轮未使用平台开发者工具完成原生验收，用户确认暂无 AppID 与域名；M5 保持「开发完成、原生待验」。
