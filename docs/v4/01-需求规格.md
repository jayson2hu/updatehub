## 2 产品目标与范围

### 2.1 产品定位

版本喵是群友整理的软件更新站。群主（管理员）把常用软件的官方新版本整理出来，附上「要不要更新」的建议、更新内容、安装教程和官方下载入口，然后把链接发到微信群、小红书群。访客主要是中国手机用户，在微信 / 小红书里点开链接，无需登录即可查看和下载。

站点只整理官方信息，不存放安装包；所有下载都跳转到官方来源（或官方提供的网盘备用链接）。

### 2.2 本期目标

1. 访客打开任何一个软件链接，3 秒内看懂「这个版本要不要更新」，并能一步找到适合自己设备的官方下载。
2. 访客在小红书内置浏览器打开时，能被清楚引导到系统浏览器完成下载。
3. 访客不注册也能收藏软件、在收藏有新版时看到提醒，换手机时用同步码恢复收藏。
4. 访客可以反馈「能用 / 有问题」和提交「想要的软件」，帮助群主和其他群友判断。
5. 群主在后台一个弹层内完成「发布更新 → 生成群通知 → 复制」，并能在工作台看到需要处理的问题。
6. 保留现有 3 个广告位，可按位置开关，并能看到近 7 天曝光与点击。
7. 网站、微信小程序、小红书小程序视觉和功能一致（小程序下载改为复制链接）。

### 2.3 本期范围

| 端 | 内容 |
| --- | --- |
| 网站前台 | 首页、软件库、软件详情、公告列表、公告详情、搜索、我的；7 个弹层中的 5 个访客弹层 |
| 网站后台 | 工作台、发布更新弹层、发公告弹层、软件管理、版本编辑、公告管理、用户反馈处理、想要的软件、广告管理、站点设置 |
| 小程序 | 微信、小红书两端：最新（首页）、软件库、详情、公告列表、公告详情、搜索、我的 |
| 旧版 | 旧 UpdateHub 页面下线（代码保留），旧分享链接继续可用 |

### 2.4 不做（本期明确排除）

| 不做项 | 说明 |
| --- | --- |
| 自动检测新版本 | 不抓取、不轮询官方站点；所有版本由群主手工发布。设计稿工作台中「自动检查发现，需要你确认后发布」的待办本期不实现（见 §10 问题清单） |
| 开屏 / 插屏广告 | 不做任何全屏、弹窗、下载前中转类广告 |
| 用户账号 | 访客无注册、无登录；「微信 / 邮件推送新版本」仅以「规划中」禁用态展示 |
| 托管安装包 | 不上传、不存储、不代理任何安装包；系统不主动请求下载地址 |
| 新增广告位 | 只保留首页信息流、详情页下载区下方（手机）、电脑右侧栏 3 个位置 |

另外本期也不做：评论区、用户上传内容、站内消息推送、多管理员角色权限细分、第三方广告 SDK 接入。

## 3 用户角色

| 角色 | 描述 | 主要场景 | 权限 |
| --- | --- | --- | --- |
| 访客 | 群成员或经分享进入的人，多数用手机、在微信 / 小红书内打开 | 看某软件新版要不要更新、下载、看安装教程；收藏常用软件；反馈能不能用；提交想要的软件 | 免登录访问全部公开内容；本地保存收藏、浏览记录、常用设备、反馈记录 |
| 群主 / 管理员 | 站点运营者，通常 1–3 人，用电脑维护 | 发布新版本并复制群通知；发公告；处理反馈和想要的软件；开关广告；修改站点设置 | 账号密码登录后台（沿用现有 `admin_user` / 会话 / CSRF 机制）；所有写操作记审计日志 |

本期管理员之间不区分角色权限。后台只在电脑端提供；手机访问后台给出「请在电脑上打开后台」提示即可（P2 适配）。

## 4 术语表

| 术语 | 定义 |
| --- | --- |
| 软件（software） | 一个被收录的应用，有固定 `slug`（创建后不可改），可支持多个设备 |
| 设备（platform） | 取值 `android` / `ios` / `tv` / `desktop`；界面短名「安卓 / 苹果 / 电视 / 电脑」，全名「安卓手机 / 苹果手机 / 电视盒子 / 电脑」；图标 📱 🍎 📺 💻 |
| 版本（release） | 某软件在某设备上的一个版本记录。新版本新建记录，不覆盖旧记录 |
| 当前版本 | 同一软件同一设备下，已发布且发布时间最新的版本 |
| 上一版本 | 当前版本之前的一个已发布版本，用于「3.2.0 → 3.2.1」对比展示 |
| 更新建议（advice） | 群主对某个版本给出的建议，四档：`recommended` 建议更新 / `wait` 可以等等 / `hold` 先别更新 / `optional` 可选更新。与可用性状态相互独立 |
| 可用性状态（status） | 现有字段：`normal` 正常 / `attention` 需留意 / `unavailable` 暂不可用，配合 `status_reason` 说明。描述「下载入口能否用」，不表达「要不要更新」 |
| 稳定版（stable_release） | 当建议为「先别更新」时，群主指定的同设备下推荐下载的旧版本 |
| 建议说明（advice_note） | 一句话解释建议原因，展示在详情页结论条，例如「修复了播放卡顿，旧版也还能用，不着急。」 |
| 一句话说明（summary） | 版本摘要，展示在卡片和群通知中，例如「修复播放卡顿，新增 0.5x–2x 倍速播放」 |
| 更新条目 | 版本更新内容，按类型 `added` 新增 / `fixed` 修复 / `improved` 优化 / `known_issue` 已知问题 分组 |
| 官方下载 | 版本的主下载入口（官方网站或 App Store 链接） |
| 备用下载 | 官方提供的网盘链接与提取码，「官网打不开时用」；苹果版无备用 |
| 软件分类 | `video` 影视 / `netdisk` 网盘 / `tool` 工具 / `music` 音乐 / `note` 笔记 / `reading` 阅读 / `browser` 浏览器 / `other` 其他 |
| 公告类型 | `group` 群公告 / `usage` 使用提醒 / `maintenance` 维护通知 |
| 置顶 / 已结束 | 公告可置顶并设有效期；到期后自动退出置顶，列表与详情显示「已结束」 |
| 收藏 | 访客在本机保存的软件列表，不上传个人信息 |
| 有新版（红点） | 收藏的软件在访客上次查看该软件详情后有新的已发布版本 |
| 同步码 | 10 位字符的一次性凭证，30 天有效，用于在另一台设备恢复收藏 |
| 反馈 | 访客对某软件某设备当前版本的「能正常用 / 有问题」投票，「有问题」可附类型与说明 |
| 想要的软件 | 访客提交的收录请求，按名称归一后合并计票 |
| 群通知 | 发布更新后生成、供群主复制到群里的纯文本 |
| 应用内浏览器 | 微信、小红书等 App 内置浏览器。小红书内不能直接下载安装包 |
| 广告位 | `home_feed` 首页信息流 / `detail_body` 详情页下载区下方（手机）/ `desktop_sidebar` 电脑右侧栏 |
| 曝光 / 点击 | 见 §7 数据口径 |
| 约 | 估算值标记；收藏数、看过人数为估算，后台数值前标「约」 |

## 5 功能需求

编号规则：`R-模块-序号`。除表中特别说明外，所有需求同时适用于手机与电脑布局；小程序差异在 R-MINI 中说明。

> 说明：为避免在各页面重复描述，全站共用的外壳与行为单列为 R-GLOBAL 模块。

### 5.0 全站通用（R-GLOBAL）

#### R-GLOBAL-01 站名与品牌
- 描述：站名、Logo 字形、站点一句话介绍由后台「站点设置」配置。默认站名「版本喵」，Logo 字形默认「喵」（站名首字，可单独设置）。站名出现在顶栏、页脚、首页概览、海报、群通知、页面标题。
- 优先级：P0
- 验收标准：
  - Given 后台把站名改为「软件上新了」、字形改为「新」并保存，When 刷新任一前台页面与小程序，Then 顶栏、页脚、首页概览首行「{站名} · 10月第3周」、分享海报、群通知首行「【{站名}】」、浏览器标题全部显示新站名，无一处残留「版本喵」或「更新小站」。
  - 站名长度限制 2–8 个汉字（或 16 个字符），超长保存时报错「站名最多 8 个字」。

#### R-GLOBAL-02 手机顶栏与底栏
- 描述：
  - 底栏固定 4 项：「🏠 首页」「📦 软件库」「📢 公告」「👤 我的」。当前页高亮；进入软件详情时「软件库」高亮，进入公告详情时「公告」高亮。「我的」右上角显示红色数字角标 = 有新版的收藏数（0 时不显示）。搜索页不显示底栏。
  - 顶栏按页面不同：首页为 Logo + 站名 + 🔍（进搜索）+ ⭐（进我的，有新版时带红点）；软件库为标题「软件库」+ 🔍；公告为标题「群公告」；我的为标题「我的」；详情为「‹ 返回」+ 软件名（单行省略）+ 收藏按钮 +「↗」分享；公告详情为「‹ 返回」+「公告详情」+「↗」复制链接；搜索为「‹ 返回」+ 搜索框。
- 优先级：P0
- 验收标准：
  - 在 360 / 390 宽度下，顶栏和底栏不换行、不横向溢出；底栏每项点击区域 ≥ 44×44px。
  - 有 2 个收藏软件有新版时，底栏「我的」角标显示「2」，首页顶栏 ⭐ 显示红点；全部已读后两者消失。
  - 详情页「‹」返回上一页面；无上一页（直接从分享链接进入）时返回首页。

#### R-GLOBAL-03 电脑顶部导航
- 描述：顶部导航吸顶，高 64px，半透明白底带模糊。左侧 Logo + 站名；导航项「首页」「软件库」「群公告」「我的收藏」（有新版时带数字角标）；右侧搜索框（占位「搜软件名或用途」），输入第一个字符即进入搜索页并保持输入焦点。后台页面不显示此导航。
- 优先级：P0
- 验收标准：
  - 在 1440 宽度下内容区最大宽 1120px 居中；滚动时导航保持在顶部。
  - 在导航搜索框输入「网盘」，跳转至搜索页，搜索框内为「网盘」且光标在末尾，结果即时显示。

#### R-GLOBAL-04 页脚
- 描述：
  - 手机：居中两行「{站名} · 群友整理的软件更新」「只整理官方信息，不存放安装包 · 免责声明」。
  - 电脑：左侧「**{站名}** · 群友整理的软件更新，只整理官方信息，不存放安装包」与「备案号：{ICP备案号}」；右侧链接「关于本站」「隐私说明」「免责声明」「群主后台」。
- 优先级：P0
- 验收标准：备案号来自站点设置，为空时整行隐藏（不显示「待填写」）；「群主后台」跳转 `/admin`，未登录时进登录页。

#### R-GLOBAL-05 设备识别与默认设备
- 描述：进入软件详情时按以下顺序决定默认设备：① URL 参数 `platform`；② 访客在「我的 → 常用设备」设置的设备（若该软件支持）；③ 按 User-Agent 识别的本机设备（安卓 / 苹果 / 电脑；电视无法识别）；④ 该软件支持的第一个设备（顺序 android、ios、tv、desktop）。识别出的本机设备在设备选择格上显示「本机」角标。
- 优先级：P0
- 验收标准：
  - Given 安卓手机、未设常用设备，When 打开「光幕影视」，Then 默认选中「安卓」，该格显示「本机」，标题旁显示「已自动识别」。
  - Given 常用设备设为「电视盒子」，When 打开支持电视的软件，Then 默认选中「电视」；打开不支持电视的软件时回落到第 ③ 步。
  - Given URL 带 `?platform=desktop`，Then 无论本机是什么设备都选中「电脑」。

#### R-GLOBAL-06 小红书内打开提示条
- 描述：识别为小红书内置浏览器时，在手机首页和详情页顶栏下方显示提示条：「⚠ **在小红书里无法直接下载** / 点右上角「···」→「在浏览器打开」」，右侧按钮「怎么做」打开引导弹层（R-SHEET-02）。在小红书内点击任何下载按钮时不跳转，改为打开引导弹层。微信内置浏览器不显示提示条（微信可正常跳转官网；如后续发现无法下载，同样逻辑扩展到微信，由配置开关控制，P1）。
- 优先级：P0
- 验收标准：
  - 用小红书 UA 打开详情页，提示条可见；点「官方下载 安卓版」弹出引导弹层，页面不跳转。
  - 普通浏览器打开不显示提示条，下载按钮直接新窗口打开官方地址。

#### R-GLOBAL-07 复制与轻提示（toast）
- 描述：所有「复制」动作写入剪贴板后底部显示 toast，约 1.9 秒后消失；复制失败显示「复制失败，请长按文字手动复制」，并同时展示可选择的文本（输入框或高亮文字），便于手动复制。toast 使用 `role="status"` 被读屏播报。
- 优先级：P0
- 验收标准：在禁用剪贴板 API 的环境中点击「复制链接」，出现失败提示且页面上出现可长按选择的完整链接。

#### R-GLOBAL-08 新版提醒（红点）判定
- 描述：本地记录每个收藏软件「上次查看时的最新版本发布时间」。若该软件任一设备出现更晚发布的版本，则视为「有新版」。打开该软件详情、点「全部已读」均标记为已读。新收藏的软件立即视为已读。「我的 → 更新提醒 → 打开网站时，提醒收藏的软件有新版」开关关闭后不显示任何红点与角标。
- 优先级：P0
- 验收标准：收藏 A 后，后台为 A 发布新版本；刷新首页可见「收藏的软件有更新」区块、底栏角标 1；打开 A 详情后返回首页，区块与角标消失。

#### R-GLOBAL-09 说明页面
- 描述：提供「关于{站名}」「隐私说明」「免责声明」三个静态页面，内容由站点设置维护（纯文本段落）。隐私说明须写明：不收集个人信息，反馈匿名；收藏保存在本机；统计仅为按日汇总次数，不记录 IP 和访客标识，保留 90 天。
- 优先级：P1
- 验收标准：三个页面可从页脚和「我的」底部入口访问；内容修改后立即生效。

### 5.1 首页（R-HOME）

#### R-HOME-01 本周概览（Hero）
- 描述：首页顶部蓝色渐变卡片。第一行「{站名} · {M}月第{N}周」；主标题「本周 {X} 个软件更新」；统计胶囊「✓ {a} 个建议更新」「✕ {b} 个先别更新」「📢 {c} 条重要公告」；底部伪搜索框「🔍 搜软件名或用途，例如“看电视”」，点击进入搜索页。
- 口径：「本周」= 自然周（周一 00:00 至周日 24:00，北京时间）；X = 本周发布的版本条目数（同一软件同日同版本多设备合并为 1 条，与信息流卡片一致）；a / b = 其中建议为 recommended / hold 的条数；c = 当前有效（未结束）且重要程度为「重要」的公告数。某项为 0 时隐藏该胶囊。「第 N 周」= 当月第几周（以周一所在月份计）。
- 优先级：P0
- 验收标准：
  - 本周发布 7 条、其中 5 条建议更新、1 条先别更新、1 条重要公告时，显示「本周 7 个软件更新」「✓ 5 个建议更新」「✕ 1 个先别更新」「📢 1 条重要公告」。
  - 本周无更新时主标题显示「本周暂无软件更新」，统计胶囊不显示。

#### R-HOME-02 电脑端概览右侧公告

### 5.3 软件详情（R-DETAIL）

URL：`/software/{slug}`，支持 `?platform={android|ios|tv|desktop}&release={版本ID}`（见 R-LEGACY-02）。

#### R-DETAIL-01 头部
- 描述：图标（手机 64px、电脑 80px）、分类「🎬 影视 · {开发者}」、软件名 H1、一句话简介。电脑端头部右侧有「☆ 收藏 / ★ 已收藏」和「↗ 分享」按钮；手机端这两个操作在顶栏。电脑端顶部有面包屑「首页 › {分类} › {软件名}」。
- 优先级：P0
- 验收标准：面包屑「{分类}」点击进入软件库对应分类。

#### R-DETAIL-02 关键数字
- 描述：三格：「{p}% 反馈能用」（绿色）、「{n} 人收藏」、「{M月D日} 最近更新」。p 取当前所选设备当前版本；反馈 < 5 条时显示「—」与「反馈较少」。收藏数为估算值（§7.3）。
- 优先级：P0
- 验收标准：切换设备后三格数据随之变化（收藏数为软件级不变）。

#### R-DETAIL-03 更新建议结论条
- 描述：彩色结论条，左侧圆形图标，标题「{建议} · {设备短名}版 {版本号}」，下方建议说明。四档：

  | --- | --- | --- | --- |
  | recommended | 建议更新 | ✓ | 绿 |
  | wait | 可以等等 | ! | 橙 |
  | hold | 先别更新 | ✕ | 红 |
  | optional | 可选更新 | ○ | 灰 |

- 优先级：P0
- 验收标准：选中「云盘助手 电脑」时显示红色「先别更新 · 电脑版 4.1.0」与说明「4.1.0 有登录问题。还没更新的先别更新；已经更新的先用网页版，或者装回 4.0.6。」；结论文字不只靠颜色区分（同时有图标和文字）。

#### R-DETAIL-04 设备选择
- 描述：区块标题手机为「选择你的设备」+ 右侧「已自动识别」，电脑为「下载」。4 格等宽：📱 安卓 / 🍎 苹果 / 📺 电视 / 💻 电脑。软件不支持的设备置灰禁用，提示「暂无此设备版本」。选中格蓝色描边浅蓝底。切换设备后版本、结论、下载、更新内容、教程、FAQ、版本记录、系统要求全部同步切换，并重置为该设备最新版本；URL 的 `platform` 同步更新（replaceState，不新增历史）。
- 优先级：P0
- 验收标准：「星河TV」只支持电视和安卓，苹果、电脑格不可点击且有禁用样式；切换到「电视」后主按钮变为「⬇ 官方下载 电视版」。

#### R-DETAIL-05 版本选择
- 描述：该设备已发布版本 > 1 时显示横向版本条：每项「**{版本号}** / {标签} · {日期}」，标签为「最新」（当前版本）、「有问题」（建议为 hold 的旧版）、「旧版」。选中旧版时：显示灰色提示「你正在看旧版本 {x}。没有特别需要，建议下载最新版 {最新}。」；主按钮文字追加版本号；URL 写入 `release`。只有 1 个版本时不显示版本条。
- 优先级：P0
- 验收标准：在版本记录中点「下载这个版本」等同于在版本条选中该版本，手机端自动滚动到页面顶部的下载区。

#### R-DETAIL-06 主下载按钮
- 描述：大号主色按钮（高 52px，整宽）：
  - 安卓 / 电视 / 电脑：「⬇ 官方下载 {设备短名}版」，旧版为「⬇ 官方下载 {设备短名}版 {版本号}」。
  - 苹果：「⬇ 去 App Store 下载」。
  - 点击在新窗口打开该版本的官方下载地址；小红书内改为打开引导弹层；记录一次下载点击（§7.5）。
  - 该版本无官方链接时按钮禁用，文案「暂无下载链接」。
  - 可用性状态 `unavailable` 时见 R-DETAIL-21。
- 优先级：P0
- 验收标准：每个设备 / 版本组合只打开该组合自己的链接，不会把电视版链接用于安卓。

#### R-DETAIL-07 「先别更新」下载区

  - 苹果：①点按钮跳转到 App Store ②点「获取」或「更新」，按提示验证 ③打开后按提示允许网络权限；提示：苹果手机只能从 App Store 安装，本站不提供其他安装方式。
  - 电视：①在手机或电脑上下载电视版安装包 ②用「当贝助手」或 U 盘把安装包传到电视 ③在电视的文件管理里找到安装包，点击安装；提示：电视第一次装软件时，需要在「设置 → 安全」里打开“允许安装未知来源”。
  - 电脑：①点「官方下载」，保存安装包 ②双击安装包，按提示点“下一步” ③被杀毒软件拦截时，选择“允许”或“信任”；提示：安装路径尽量不要有中文。
- 优先级：P0
- 验收标准：切换设备后教程标题和步骤切换为对应设备。

#### R-DETAIL-15 标签页：常见问题
- 描述：折叠列表（`details/summary`），问题行高 ≥ 46px，右侧「+ / −」。来源同教程（软件 × 设备，缺省用通用模板）。末尾固定一项「以上都没解决？」：「点下方“有问题”提交反馈，或在群里 @群主，说一下设备型号和卡在哪一步。」
- 优先级：P0
- 验收标准：键盘 Enter / Space 可展开收起；默认全部收起。

#### R-DETAIL-16 标签页：版本记录
- 描述：竖向时间线，当前版本节点为实心蓝点，hold 版本节点为红圈。每项：版本号、建议标签、日期、一句话说明；旧版本追加链接「下载这个版本」。无更早版本时显示「暂无更早的版本记录」。
- 优先级：P0
- 验收标准：点「下载这个版本」选中该版本（同 R-DETAIL-05）。

#### R-DETAIL-17 标签页：软件信息
- 描述：两列信息表：开发者、官方网站（「{域名} ↗」新窗口）、支持设备（全名顿号分隔）、系统要求（当前设备）、安装包大小（当前版本）、收费（如「免费，含可选内购」）、标签（小标签）、收录时间（「2026年8月」）。
- 优先级：P0
- 验收标准：字段为空的行隐藏。

#### R-DETAIL-18 反馈：能用 / 有问题
- 描述：卡片标题「更新后能正常用吗？」，右侧「{N} 人反馈」。两个按钮「👍 能正常用 · {o}」「👎 有问题 · {b}」，下方能用率条（绿色占比）和文字「{p}% 的群友反馈能正常使用」，p < 60% 且反馈 ≥ 10 条时追加红字「· 问题较多，建议先等等」。
  - 反馈对象 = 当前所选设备的当前版本（不对旧版反馈；选中旧版时卡片标题改为「最新版 {x} 能正常用吗？」）。
  - 点「能正常用」：立即计票，按钮选中，toast「谢谢你的反馈 👍」。
  - 点「有问题」：计票并打开问题弹层（R-SHEET-04）补充类型与说明；关闭弹层不撤销投票。
  - 再次点击已选按钮撤销投票；点另一个按钮改投。每台设备对同一版本只保留一票（本地记录 + 服务端限流）。
- 优先级：P0
- 验收标准：投票后数字 +1 并同步到「我的 → 我的反馈」；刷新页面保持选中态；同一版本改投后两边数字一减一加。

#### R-DETAIL-19 相关公告
- 描述：存在关联该软件的公告（含已结束）时，显示「相关公告」卡片，内为完整公告卡片（同 R-ANN-02）。
- 优先级：P1
- 验收标准：无关联公告时整块隐藏；已撤回公告不显示。

#### R-DETAIL-20 大家还在看
- 描述：横向卡片最多 4 个：同分类软件优先，不足用其他分类热门补齐；每张含小图标、名称、当前版本号。
- 优先级：P1
- 验收标准：不包含当前软件、下架软件。

#### R-DETAIL-21 可用性状态展示
- 描述：可用性状态与更新建议独立展示：
  - `attention`：在下载按钮上方显示橙色提示「⚠ {status_reason}」，按钮可用。
  - `unavailable`：显示红色提示「这个版本暂时无法下载：{status_reason}」，主按钮禁用为「暂时无法下载」；若有稳定版且稳定版可用，主按钮改为「⬇ 下载稳定版 {x}」。
- 优先级：P0
- 验收标准：后台把某版本设为 unavailable 并填原因，前台详情立即显示原因、按钮禁用；信息流卡片不受影响（仍显示建议标签）。

#### R-DETAIL-22 浏览与收藏记录
- 描述：打开详情即：写入本地「最近看过」（去重、最多 6 个、最新在前）；对已收藏软件标记已读；按 §7.2 上报一次看过（本地当天去重）。
- 优先级：P0
- 验收标准：连续打开 7 个软件，「最近看过」只保留最近 6 个。

### 5.4 公告（R-ANN）

#### R-ANN-01 公告列表与筛选
- 描述：路由 `/announcements`。电脑标题「群公告」+ 说明「重要通知、使用提醒和维护安排。」（最大宽 820px）。类型 chips：「全部 / 群公告 / 使用提醒 / 维护通知」。排序：有效置顶在前，其余按发布时间倒序；已结束公告排在未结束之后。列表 20 条一页，加载更多。
- 优先级：P0
- 验收标准：选「维护通知」只显示该类型；空时显示「📭 暂时没有这类公告」。

#### R-ANN-02 公告卡片
- 描述：左侧 4px 色条（重要为红、使用提醒为金、其他为蓝、已结束为灰且整卡 65% 透明度）。顶部行：「📌 置顶」金标签（有效置顶时）、类型标签（重要为红、使用提醒为金、其他为蓝）、「已结束」灰标签、右侧日期；标题（15.5px 粗体）；摘要 2 行；底部关联软件小标签 + 右侧「{n} 人看过」。
- 优先级：P0
- 验收标准：已结束公告即使原设置为置顶也不显示「📌 置顶」且不排在前面。

#### R-ANN-03 公告详情
- 描述：路由 `/announcements/{slug}`。已结束时顶部灰色提示「这条公告已结束，内容仅供参考。」；元信息行「📌 置顶」「类型」「{M月D日}发布 · 有效期到 {M月D日} · {n} 人看过」；标题 H1；正文段落（16px、行高 1.8，纯文本段落，支持列表）；可选配图与外链；「相关软件」列表（图标、名称、「版本 · 日期」、建议标签，点击进详情）；底部「🔗 复制公告链接」，toast「公告链接已复制」。电脑端面包屑「群公告 › 详情」，内容卡片最大宽 760px。
- 优先级：P0
- 验收标准：撤回的公告访问返回 404 页面「这条公告已经撤回」；到期公告可访问并显示已结束提示。

#### R-ANN-04 置顶与有效期
- 描述：公告可设置置顶与有效期；超过有效期自动视为已结束（无需定时任务，读取时计算），退出置顶，不在首页群公告区块与 Hero 右栏出现。
- 优先级：P0
- 验收标准：有效期设为昨天的置顶公告，首页不再出现，公告列表中显示「已结束」并排在后面。

#### R-ANN-05 公告重要程度
- 描述：公告重要程度沿用 `normal` 普通 / `important` 重要 / `urgent` 紧急；界面上 important 与 urgent 均按「重要」红色样式展示，并计入首页「重要公告」数。
- 优先级：P1
- 验收标准：重要公告卡片左侧色条与类型标签为红色。

### 5.5 搜索（R-SEARCH）

#### R-SEARCH-01 入口
- 描述：入口有：首页 Hero 伪搜索框、手机首页 / 软件库顶栏 🔍、电脑导航搜索框。搜索页路由 `/search?q=`。手机搜索页顶栏为「‹」+ 搜索框（占位「搜软件名、用途或公告」，进入时自动聚焦），无底栏；电脑为页面内大搜索框（高 52px，最大宽 820px）。
- 优先级：P0
- 验收标准：输入时实时出结果（防抖 ≤ 300ms），URL `q` 参数同步更新，刷新后保留结果。

#### R-SEARCH-02 空查询状态
- 描述：未输入时显示「大家在搜」热门词 chips（前 3 个带「🔥 」），点击填入搜索框；下方「最近看过」（同 R-DETAIL-22 的本地记录），右侧「清空」，清空后 toast「已清空」。
- 热门词来源：后台站点设置可配置最多 8 个；未配置时取近 7 天有结果的搜索词前 5（§7.6）。
- 优先级：P0
- 验收标准：清空后「最近看过」显示空态「还没有看过的软件」。

#### R-SEARCH-03 匹配范围
- 描述：不区分大小写、全半角归一后包含匹配：软件名称、别名、简介、标签、分类名；公告标题与正文。下架软件和撤回公告不参与。
- 优先级：P0
- 验收标准：搜「影视」能命中分类为影视的所有软件；搜软件别名能命中该软件。

#### R-SEARCH-04 结果展示
- 描述：分两组：「软件 · {N}」（列表行：小图标、名称、简介单行、建议标签）、「公告 · {N}」（公告卡片：标题 + 日期）。命中文字黄色高亮（`mark`）。软件组在前。
- 优先级：P0
- 验收标准：搜「网盘」时软件「云盘助手」的简介「网盘批量下载…」中「网盘」高亮；高亮不引入 HTML 注入（关键词含 `<b>` 时原样显示）。

#### R-SEARCH-05 无结果
- 描述：「🔍 没找到“{q}”」「换个关键词试试，或者告诉群主你想要什么软件」+ 按钮「＋ 我想要这个软件」，打开 R-SHEET-06，软件名称预填为 q。
- 优先级：P0
- 验收标准：提交后 toast「已提交，收录后会在“我的”里显示」。

### 5.6 我的（R-ME）

#### R-ME-01 头部

#### R-ME-06 最近看过
- 描述：「🕘 最近看过」横向卡片（最多 6 个）：小图标、名称、当前版本号。空时隐藏整卡。

- 优先级：P1
- 验收标准：三个入口可达。

### 5.7 弹层（R-SHEET）

#### R-SHEET-01 弹层通用行为
- 描述：手机为底部弹出 sheet（顶部圆角 22px、抓手条、最大高 88%，内容可滚动）；电脑为居中对话框（宽 480px）。遮罩为深色半透明。`role="dialog"`、`aria-modal="true"`、有标题。点遮罩、按 Esc、点「关闭」按钮关闭；打开时焦点移入弹层首个可交互元素，关闭后焦点回到触发按钮；打开期间页面不滚动、焦点不移出弹层。表单输入未提交时点遮罩关闭不提示（内容短，P2 可加确认）。
- 优先级：P0
- 验收标准：键盘可完成打开 → 填写 → 提交 → 关闭全流程；读屏能读出弹层标题。

#### R-SHEET-02 小红书内打开引导
- 描述：标题「请在浏览器中打开后下载」，说明「小红书里不能直接下载安装包，按下面做：」。三步（带编号圆点与右侧示意按钮）：「1 点右上角的三个点 ···」「2 选择「在浏览器打开」 🌐 在浏览器打开」「3 在浏览器里再点「官方下载」 ⬇ 官方下载」。黄色提示「找不到这个选项？复制链接，打开手机自带的浏览器，粘贴到地址栏。」主按钮「复制链接」（复制当前软件带设备 / 版本参数的链接，toast「链接已复制，去浏览器粘贴打开」），次按钮「关闭」。
- 优先级：P0
- 验收标准：在首页打开时复制首页链接；在详情页打开时复制当前详情链接（含 platform、release）。

#### R-SHEET-03 分享
- 描述：标题「分享这个软件」。海报预览：上部蓝色渐变区（图标、「{软件名} {版本}」、「{建议} · {日期}」、一句话说明），下部二维码 +「扫码查看下载和教程」「{站名} · 群友整理的软件更新」。三个按钮：「🔗 复制链接」（toast「链接已复制」）、「💬 复制群文案」（toast「群通知文案已复制」）、「🖼 保存海报」（生成 PNG：手机触发下载或提示长按保存，toast「海报已保存到相册」或「长按图片保存」）。
  - 分享的设备与版本取当前页面所选；链接带 `platform`。
  - 群文案使用与发布更新相同的群通知模板（R-SHEET-07 / §UI 规范 文案），而非设计稿的单行格式（见 Q9）。
  - 支持系统分享（`navigator.share`）时可额外显示「更多…」（P2）。
- 优先级：P0（保存海报 P1）
- 验收标准：360 宽下三个按钮不溢出（允许换成两行或竖排）；海报中二维码扫描后打开对应软件与设备。

#### R-SHEET-04 反馈问题
- 描述：标题「遇到了什么问题？」，说明「{软件名} · {设备全名}　匿名提交，群主会看到」。问题类型 chips 单选（必选）：闪退 / 装不上 / 下载不了 / 登录不了 / 链接失效 / 其他。「补充说明（选填）」多行输入，占位「比如：手机型号、卡在哪一步」，最多 300 字，显示字数「0/300」。按钮「提交反馈」，成功 toast「已提交，群主会尽快处理」。未选类型时按钮禁用。
- 服务端记录：软件、设备、版本、类型、说明、提交时间；不记录 IP、UA、访客标识。
- 优先级：P0
- 验收标准：输入第 301 个字时无法继续输入；说明中包含 HTML 时后台原样显示为文本；同一设备 1 分钟内重复提交被限流并提示「提交太频繁，请稍后再试」。

#### R-SHEET-05 同步码
- 描述：标题「同步收藏」，说明「不用注册，用同步码在另一台设备上恢复收藏。」分段切换「生成同步码 / 输入同步码」。
  - 生成：大号等宽显示同步码（10 位，按 5+5 分组显示，如 `XB7K2-M9Q4T`），下方「包含你的 {N} 个收藏 · 30 天内有效 · 不包含任何个人信息」，按钮「复制同步码」，toast「同步码已复制，在新设备上输入即可」。没有收藏时提示「还没有收藏，先去收藏几个软件吧」且不生成。
  - 输入：标签「在另一台设备上生成的同步码」，大号居中输入框（占位如 `XB7K2-M9Q4T`，自动转大写、忽略空格与短横线），按钮「恢复收藏」，说明「恢复后会和这台设备上的收藏合并，不会覆盖。」成功 toast「已恢复，新增 {k} 个收藏」并关闭弹层。
- 规则：
  - 同步码字符集为大写字母和数字，排除易混字符 0 O 1 I L；服务端只保存同步码哈希与收藏软件 slug 列表、创建时间、过期时间。
  - 有效期 30 天，期内可多次使用；重新生成会作废旧码并生成新码，内容为当时收藏。
  - 错误：码不存在或格式错误「同步码不对，请检查后重试」；已过期「同步码已过期，请在原设备重新生成」；恢复中包含已下架软件时自动跳过。
  - 恢复接口限流：同一来源每分钟最多 5 次、每天 30 次。
- 优先级：P0
- 验收标准：设备 A 收藏 3 个生成码；设备 B 已有 1 个（与 A 有 1 个重复）输入后，B 共 3 个收藏，toast「已恢复，新增 2 个收藏」。

#### R-SHEET-06 想要的软件
- 描述：标题「想要什么软件？」，说明「告诉群主，收录后会在“我的 → 想要的软件”里显示。」字段：软件名称（必填，2–30 字，占位「例如：某某输入法」，从搜索进入时预填关键词）、用在什么设备（chips 多选：📱 安卓 / 🍎 苹果 / 📺 电视 / 💻 电脑，可不选）、用途（选填，≤ 50 字，占位「比如：电视上看直播」）。按钮「提交」，toast「已提交，收录后会在“我的”里显示」。
- 规则：服务端按名称归一（去首尾空格、全角转半角、英文转小写、去除内部空格与常见后缀如「app」「软件」「电视版/TV版」只用于匹配不改原文）合并到同一请求并 +1 票；设备合并计数。同一设备对同一请求只计 1 票（本地记录）。
- 优先级：P0
- 验收标准：两台设备分别提交「XX输入法」「xx 输入法」，后台只出现 1 条，显示「2 人想要」。

#### R-SHEET-07 发布更新（后台）
- 描述：后台工作台、侧栏「🚀 发布更新」、待办「去发布」均可打开（电脑居中对话框，宽可放大到 560px）。字段：
  - 软件（搜索下拉选择已有软件，必选）；设备（单选或多选，仅显示该软件支持的设备）；新版本号（必填）；
  - 更新建议 chips：建议更新 / 可以等等 / 先别更新 / 可选更新（默认建议更新）；选「先别更新」时出现「稳定版」下拉（同设备已发布版本），可不选；
  - 一句话说明（必填，≤ 40 字）；
  - 官方下载链接（每个所选设备一行，标签「官方下载链接（{设备}）」，自动带出上一版本链接供修改）；
  - 「更多内容」折叠：建议说明、更新条目（新增 / 修复 / 优化 / 已知问题）、备用网盘链接与提取码、安装包大小，或点「在完整编辑页打开」跳到版本编辑（R-ADMIN-10）。
  - 群通知预览：随输入实时更新（模板见 UI 规范 §8.4）。
  - 按钮「存草稿」「发布并复制群通知」。发布成功 toast「已发布，群通知已复制」并关闭；复制失败时弹层不关闭，预览框文本全选供手动复制。
- 优先级：P0
- 验收标准：
  - 修改版本号输入框，预览中第一行版本号同步变化，无需点击按钮。
  - 选择多个设备发布同版本号，前台信息流合并为 1 张卡片。
  - 链接不是 http(s) 时提示「请填写完整的 http(s) 链接」。

#### R-SHEET-08 发公告（后台）
- 描述：字段：标题（必填，≤ 40 字）、类型 chips（维护通知 / 群公告 / 使用提醒）、正文（必填，纯文本段落）、重要程度（普通 / 重要）、置顶（开关）+ 有效期（日期，可空）、关联软件（多选，可空）。按钮「存草稿」「发布并复制群通知」。公告群通知模板：「【{站名}】{标题}\n{正文首段}\n\n详情 👇\n{公告链接}\n（小红书里打不开就点右上角···，选“在浏览器打开”）」。
- 优先级：P0
- 验收标准：发布后前台公告列表立即出现；存草稿不出现在前台。

### 5.8 后台（R-ADMIN）

后台仅电脑使用，路由 `/admin/*`，沿用现有登录、会话、CSRF、审计。工作台按设计稿实现；其余页面以 v5 设计稿为准，本节给出必须覆盖的功能要点。

#### R-ADMIN-01 后台框架
- 描述：左侧深色侧栏 220px：顶部 Logo +「{站名} · 后台」；「📊 工作台」「🚀 发布更新」（打开弹层）；分组「内容」：📦 软件管理、📢 公告管理；分组「用户」：💬 用户反馈（未处理数角标）、🙋 想要的软件（未处理数角标）；分组「运营」：📣 广告管理、⚙️ 站点设置；底部「← 返回网站」和退出登录。
- 优先级：P0
- 验收标准：角标数字与对应列表「未处理」筛选结果数量一致。

#### R-ADMIN-02 工作台问候与快捷操作
- 描述：标题按时段「早上好 / 中午好 / 下午好 / 晚上好，{管理员昵称，默认“群主”}」，副标题「今天有 {N} 件事需要处理」（N = 待办数，0 时「今天没有需要处理的事」）。右侧「＋ 发公告」「🚀 发布更新」。
- 优先级：P0
- 验收标准：15:00 打开显示「下午好，群主」。

#### R-ADMIN-03 工作台指标卡
- 描述：4 张卡片，每张含名称、数值、对比、近 7 天迷你柱状图（最后一天高亮）：
  1. 今日访问（页面浏览次数，§7.1），对比「↑/↓ x% 较昨天」；
  2. 下载点击（今日），对比较昨天；
  3. 反馈“有问题”（今日，红色数字），说明为占比最高的软件「{软件} 占 {n}」；
  4. 收藏总数（约，§7.3），说明「↑ {n} 本周」。
- 优先级：P0
- 验收标准：数值与 §7 定义一致；估算值前显示「约」；上升绿色、下降红色。

#### R-ADMIN-04 需要你处理
- 描述：待办列表，每项图标、标题、说明、操作按钮。来源规则：
  - 🔥 某版本近 7 天「有问题」≥ 10 且占比 ≥ 30%：「{软件} {设备}版 {版本}：{n} 人反馈有问题」，说明「{类型} {数} · …　当前标记：{建议}」，按钮「查看」→ 反馈处理页（已筛选）。
  - 🔗 某版本「链接失效」反馈 ≥ 3：「{软件} 网盘备用链接：{n} 人反馈失效」，说明「最近一次反馈：{相对时间}」，按钮「更新链接」→ 版本编辑页。
  - 🙋 想要的软件新增未处理 ≥ 1（汇总为一条），按钮「查看」。
  - 待办处理（反馈标为已处理、链接更新）后自动消失。
  - 设计稿中「自动检查发现可能有新版本」一项本期不做。
- 优先级：P0
- 验收标准：构造 47 条「有问题」反馈，工作台出现对应待办，类型分布正确。

#### R-ADMIN-05 工作台：想要的软件
- 描述：「🙋 想要的软件」卡片，「按想要人数排序」，前 5 条未处理请求：名称、「{n} 人想要」、按钮「收录」（打开新建软件页，名称预填，并将请求标记为已收录且关联该软件）。
- 优先级：P0
- 验收标准：收录后该条从卡片消失，提交者「我的」显示「已收录」。

#### R-ADMIN-06 工作台：最近发布
- 描述：「🗂 最近发布」表格（最近 5 条，右上「全部 ›」进版本列表）：软件、版本（含设备，如「3.2.1 安卓/电视」）、状态（已发布 蓝 / 草稿 灰 / 先别更新 红）、访问（该版本发布后详情看过数）、操作「复制群通知」（复制该版本完整群通知，toast「群通知已复制」）。
- 优先级：P0
- 验收标准：复制内容与发布时生成的群通知模板一致（含链接）。

#### R-ADMIN-07 工作台：广告位概览
- 描述：「📣 广告位」「近 7 天」：三行（首页信息流 / 手机 + 电脑；详情页下载区下方 / 手机；电脑右侧栏 / 电脑），每行「{曝光} 曝光 · {点击} 点击」和开关，开关即时生效。
- 优先级：P0
- 验收标准：关闭「电脑右侧栏」后，电脑首页和详情右栏不再显示广告，其他位置不受影响。

#### R-ADMIN-08 软件管理（列表 + 编辑）
- 描述：列表列：图标、名称、分类、支持设备、最新版本（按设备）、当前建议、累计看过（约）、收藏（约）、状态（上架 / 下架 / 示例）、操作（编辑、发布更新、下架/上架、查看前台）。筛选：关键词、分类、设备、上下架。编辑表单字段：名称、slug（创建后只读）、别名、分类、一句话简介、图标上传、开发者、官方网站、收费说明、标签、收录时间（默认创建日期）、支持设备、各设备系统要求、各设备安装教程（步骤 + 示意图 + 提示，可「使用通用模板」）、各设备 FAQ、截图、上下架。
- 优先级：P0
- 验收标准：slug 重复保存提示「这个链接标识已被使用」；已有版本的设备不能从支持设备移除。

#### R-ADMIN-09 版本列表
- 描述：按软件、设备、建议、状态（草稿 / 已发布 / 撤回）筛选；列：软件、设备、版本号、建议、可用性、发布时间、看过、反馈（能用/有问题）、操作（编辑、复制群通知、撤回）。
- 优先级：P0
- 验收标准：撤回后前台详情版本条不再显示该版本。

#### R-ADMIN-10 版本编辑
- 描述：字段：软件（只读）、设备（只读）、版本号、更新建议（四档）、稳定版（hold 时可选）、建议说明、一句话说明、更新条目（四类，可增删排序）、官方下载链接、备用网盘链接 + 提取码、安装包大小、可用性状态 + 原因、发布时间、草稿 / 发布。支持「沿用上一版本内容」。右侧群通知预览与「复制群通知」。
- 优先级：P0
- 验收标准：设为 hold 而未选稳定版时保存成功但提示「建议选择一个稳定版，方便群友下载」。

#### R-ADMIN-11 公告管理
- 描述：列表列：标题、类型、重要程度、置顶、有效期、状态（草稿 / 已发布 / 已结束 / 撤回）、看过、发布时间、操作（编辑、复制链接、复制群通知、撤回）。筛选：类型、状态。编辑字段同 R-SHEET-08 并增加配图、外链、摘要。
- 优先级：P0
- 验收标准：撤回后前台访问返回 404。

#### R-ADMIN-12 用户反馈处理
- 描述：两个视图：①汇总：按软件 × 设备 × 版本统计能用 / 有问题、能用率、问题类型分布；②明细：「有问题」反馈列表，列：时间、软件、设备、版本、类型、说明、状态（未处理 / 已处理 / 忽略）、操作（标为已处理、忽略、去改建议、去改链接）。筛选：软件、类型、状态、日期。批量标记。
- 优先级：P0
- 验收标准：标为已处理后侧栏角标减少；说明中的 HTML 原样文本显示。

#### R-ADMIN-13 想要的软件
- 描述：列表列：名称（归一后的展示名）、想要人数、设备分布、用途摘要（最近 3 条）、首次 / 最近提交时间、状态（处理中 / 已收录 / 暂不收录）、操作（收录→关联或新建软件、暂不收录、合并到另一条、编辑展示名）。默认按想要人数倒序。
- 优先级：P0
- 验收标准：「合并」后票数相加，被合并条目的提交者状态跟随目标条目。

#### R-ADMIN-14 广告管理
- 描述：见 R-AD 模块。页面包含：总开关；3 个位置卡片（开关、尺寸说明、近 7 天曝光 / 点击 / 点击率、当前投放素材）；投放列表（标题、位置、时间、状态、曝光、点击、操作）；新建 / 编辑投放（标题、说明、图片、目标链接、位置多选、开始 / 结束时间、草稿 / 上线）。
- 优先级：P0
- 验收标准：同 R-AD 各条。

#### R-ADMIN-15 站点设置
- 描述：站名、站点简介、ICP 备案号、关于本站 / 隐私说明 / 免责声明正文、热门搜索词（≤ 8 个）、小红书提示开关（是否对微信也显示）、广告总开关（与广告管理同一数据）、管理员昵称（工作台问候用）。
- 优先级：P0
- 验收标准：保存后前台无需重新部署即生效。

#### R-ADMIN-16 审计
- 描述：所有后台写操作（含广告开关、反馈处理、想要的软件状态变化）写入现有 `audit_log`。
- 优先级：P1
- 验收标准：每次写操作后可在审计中查到操作人、时间、对象、动作。

### 5.9 广告（R-AD）

#### R-AD-01 广告位置
- 描述：仅以下 3 个位置，不新增：

  | 位置值 | 名称 | 端 | 位置 | 形态 |
  | --- | --- | --- | --- | --- |
  | `home_feed` | 首页信息流 | 手机 + 电脑 | 首页「最新更新」第 3 张卡片之后（少于 3 张时不显示） | 横向图文：左图 116px 宽，右侧标题 1 行 + 说明「推广说明文字 · 了解详情 ›」 |
  | `detail_body` | 详情页下载区下方 | 手机 | 详情页下载卡片之后、标签栏之前 | 横幅：图高 112px（素材建议 750×220）+ 标题行「了解 ›」 |
  | `desktop_sidebar` | 电脑右侧栏 | 电脑 | 首页右栏热门之后；详情页右栏下载卡片之后 | 竖版：300×250 素材 + 标题行 |

- 优先级：P0
- 验收标准：任何页面不出现第 4 个广告位置；弹层内、下载按钮所在卡片内不出现广告。

#### R-AD-02 标注与关闭
- 描述：每个广告左上角标注「广告」（半透明黑底白字）。手机端广告右上角有「✕」关闭按钮（`aria-label="关闭广告"`，点击区域 ≥ 44px），关闭后本次会话该位置不再显示；电脑端无关闭按钮。
- 优先级：P0
- 验收标准：所有广告可见「广告」字样；关闭后刷新前不再出现，刷新后重新出现。

#### R-AD-03 与下载区隔离
- 描述：广告不得放在下载按钮旁边或同一卡片内，与主下载按钮之间至少隔一个独立卡片边界和 12px 间距；广告视觉不得使用主色按钮样式，不得出现「下载」「立即安装」等与下载按钮混淆的按钮文案（素材审核要求，后台提示）。
- 优先级：P0
- 验收标准：手机详情页广告位于下载卡片外部下方，且与底部固定操作条不相邻重叠。

#### R-AD-04 按位置开关
- 描述：广告总开关（站点设置）+ 每个位置独立开关。总开关关闭时所有位置不展示；位置关闭时该位置不展示且不留空白。开关即时生效（前台缓存 ≤ 60 秒）。
- 优先级：P0
- 验收标准：关闭 `home_feed` 后首页第 3 条之后直接是第 4 条卡片。

#### R-AD-05 投放内容
- 描述：沿用 `station_promotion`：标题、说明、图片（固定比例裁切）、目标链接（http(s)）、位置、开始 / 结束时间、草稿 / 上线。同一位置有多个有效投放时按后台排序取第一个（P2：轮播）。无有效投放时位置不显示。
- 优先级：P0
- 验收标准：结束时间已过的投放自动不展示。

#### R-AD-06 曝光统计
- 描述：广告元素可见面积 ≥ 50% 且持续 ≥ 1 秒时计 1 次曝光；同一页面加载、同一位置只计 1 次。按「日期 × 位置 × 投放」聚合计数。
- 优先级：P0
- 验收标准：广告在首屏外未滚动到时不计曝光；滚动到可见 1 秒后计数 +1。

#### R-AD-07 点击统计
- 描述：点击广告（图或标题）计 1 次点击，并在新窗口打开目标链接；点击「✕」不计点击。按「日期 × 位置 × 投放」聚合。后台展示近 7 天曝光、点击、点击率（点击 / 曝光，保留 1 位小数）。
- 优先级：P0
- 验收标准：后台数值与人工操作次数一致（允许上报失败造成的少量偏差）。

#### R-AD-08 性能隔离
- 描述：广告图片延迟加载，不阻塞首屏；加载失败时整个广告位收起；广告数据异常不影响页面其他内容。不加载任何第三方广告脚本。
- 优先级：P0
- 验收标准：把广告图片地址改为 404 后，页面无破图且无空白占位。

#### R-AD-09 小程序广告
- 描述：小程序使用同样的 3 个位置规则（电脑右侧栏除外），点击广告复制目标链接（不能跳外链），toast「链接已复制，在浏览器打开」，计 1 次点击。
- 优先级：P1
- 验收标准：小程序广告有「广告」标注，曝光点击计入同一统计。

### 5.10 小程序（R-MINI）

微信与小红书两端共用 `apps/miniprogram` 源码，经 `npm run mini:build` 生成两端产物；共用网站公开 API 与后台数据。

#### R-MINI-01 页面与底栏
- 描述：页面：最新（首页，`pages/latest`）、软件库（`pages/software`）、公告列表（`pages/announcements`）、我的（新增 `pages/me`）为底栏 4 项，文字「首页 / 软件库 / 公告 / 我的」；详情（`pages/detail`）、公告详情（`pages/announcement`）、搜索（新增 `pages/search`）为非底栏页。「我的」角标使用平台原生 tabBar badge 能力（不支持时用红点或不显示）。
- 优先级：P0
- 验收标准：两端编译通过，4 个底栏可切换，图标为新视觉 PNG（选中 / 未选中两套）。

#### R-MINI-02 首页
- 描述：同 R-HOME-01、03、04、05、06、07、08（无电脑布局）；顶部概览中的搜索框跳转搜索页；支持下拉刷新。
- 优先级：P0
- 验收标准：下拉刷新后数据更新；广告规则同 R-AD-09。

#### R-MINI-03 软件库
- 描述：同 R-LIB-01 至 04。
- 优先级：P0
- 验收标准：分类、排序、收藏星可用。

#### R-MINI-04 详情
- 描述：同 R-DETAIL（不含电脑扫码 R-DETAIL-10），差异：
  - 所有下载一律「复制链接」：主按钮文案「⬇ 复制{设备}版下载链接」（hold 时「⬇ 复制稳定版 {x} 下载链接」），点击复制官方链接，toast「链接已复制，请到浏览器粘贴打开」；苹果为「复制 App Store 链接」，并提示「也可以直接在 App Store 搜索“{软件名}”」。
  - 备用网盘：按钮「复制链接和提取码」，复制「{链接} 提取码 {code}」。
  - 官方网站行「复制」替代「↗」。
  - 复制计为下载点击。
- 优先级：P0
- 验收标准：小程序内任何位置不调用 web-view 或外链跳转；底部固定条显示复制按钮。

#### R-MINI-05 公告列表与详情
- 描述：同 R-ANN-01 至 04；详情底部「复制公告链接」复制网站公告链接；正文中的外链显示为可复制文本。
- 优先级：P0
- 验收标准：已结束提示、置顶规则与网站一致。

#### R-MINI-06 搜索
- 描述：同 R-SEARCH-02 至 05。
- 优先级：P0
- 验收标准：无结果时可提交想要的软件。

#### R-MINI-07 我的
- 描述：同 R-ME-01 至 09。收藏、最近看过、常用设备、反馈记录、想要的软件存小程序本地存储。同步码与网站互通（网站生成的码可在小程序恢复，反之亦然）。「微信 / 邮件推送」保持「规划中」禁用。
- 优先级：P0
- 验收标准：网站生成同步码，在微信小程序输入后收藏合并成功。

#### R-MINI-08 分享
- 描述：详情页、公告详情页支持平台原生分享（微信：转发给好友 / 群、朋友圈；小红书：平台提供的分享能力），分享路径保留软件 slug、设备、版本。分享弹层保留「复制链接」（网站链接）、「复制群文案」；海报为 P2。
- 优先级：P0（海报 P2）
- 验收标准：从分享卡片进入的详情页选中相同设备与版本。

#### R-MINI-09 反馈与想要的软件
- 描述：同 R-SHEET-04、R-SHEET-06、R-DETAIL-18，弹层用自定义底部弹层组件实现。
- 优先级：P0
- 验收标准：小程序提交的反馈出现在后台反馈处理列表中，来源标记为「微信小程序」/「小红书小程序」（仅来源渠道，不含用户信息）。

#### R-MINI-10 平台差异
- 描述：小程序内不显示「小红书内打开」提示条与引导弹层；不显示后台入口和「群主后台」链接；导航栏标题为站名或页面名；请求失败显示原因 +「重试」。
- 优先级：P0
- 验收标准：断网时各页面显示错误状态与重试按钮。

#### R-MINI-11 视觉一致
- 描述：小程序样式按 UI 规范 token 重做，替换现有绿色主题（`#35664a` 等）为 v4 蓝色主题。
- 优先级：P0

#### R-LEGACY-05 数据保留

## 7 数据口径

所有统计以北京时间自然日为单位，按「日期 × 维度」存为计数，不含个人信息，保留 90 天。展示累计值（看过人数、收藏数）由软件记录上的 `view_count`、`favorite_count` 累计计数字段提供（不含个人信息，不受 90 天限制）。

| 编号 | 指标 | 定义 | 维度 | 是否估算 | 展示位置 |
| --- | --- | --- | --- | --- | --- |
| 7.1 | 访问（页面浏览） | 前台任一页面加载一次计 1 次（SPA 内跳转也计）。不去重，代表浏览次数而非人数 | 日期、页面类型、渠道 | 否（浏览次数） | 后台「今日访问」 |
| 7.2 | 看过人数 | 打开软件详情时，若本机当天未上报过该软件则上报 1 次（本地当天去重）。同一人多设备、清除数据会重复计。累计值 = 历史上报总和 | 日期、软件、设备 | 是，后台标「约」 | 卡片「{n} 人看过」、热门、后台 |
| 7.3 | 收藏数 | 收藏 +1、取消 −1 上报的累计净值；同步码恢复新增的收藏也上报 +1。清除本地数据不会扣减 | 日期、软件 | 是，后台标「约」 | 详情「人收藏」、后台「收藏总数」 |
| 7.4 | 能用率 | 当前版本「能正常用」票数 /（能正常用 + 有问题）。投票改投、撤销实时更新；同一设备同一版本 1 票（本地约束 + 限流） | 版本 | 否 | 卡片、详情、后台 |
| 7.5 | 下载点击 | 点击主下载、稳定版、仍要下载、App Store、备用网盘链接、复制提取码 / 小程序复制下载链接，各计 1 次 | 日期、软件、设备、版本、入口类型 | 否 | 后台「下载点击」 |
| 7.6 | 搜索词 | 停止输入 1 秒后或回车时上报一次关键词与是否有结果；关键词截断 30 字 | 日期、关键词、有无结果 | 否 | 热门搜索、后台 |
| 7.7 | 公告看过 | 打开公告详情，本地当天去重后计 1 次 | 日期、公告 | 是 | 公告「{n} 人看过」 |
| 7.8 | 广告曝光 | 见 R-AD-06 | 日期、位置、投放 | 否 | 后台广告 |
| 7.9 | 广告点击 | 见 R-AD-07 | 日期、位置、投放 | 否 | 后台广告 |
| 7.10 | 反馈“有问题” | 当日提交「有问题」的次数（含仅投票未补充类型的） | 日期、软件、设备、版本、类型 | 否 | 后台 KPI、待办 |
| 7.11 | 想要人数 | 归一后同名请求的提交次数（同一设备本地去重） | 请求 | 是 | 后台、工作台 |

数值格式：< 1 万显示千分位「8,400」；≥ 1 万显示「1.2万」；后台估算值显示「约 9,860」。对比百分比 =（今日 − 昨日）/ 昨日，昨日为 0 时显示「—」。

## 8 验收方式概述

1. **统一验收**：网站前台、后台、两端小程序一次提交，统一验收；任一 P0 不通过即整体不通过。
2. **需求逐条核对**：按本文需求编号逐条执行验收标准，记录通过 / 不通过 / 截图；P1 不通过需列入已知问题并给出修复计划。
3. **视觉核对**：对照设计稿与 UI 设计规范，在 360、390、1440 宽度对每个页面和弹层截图比对；后台以 v5 设计稿比对。
4. **自动化检查**：`npm run lint`、`npm run typecheck`、`npm run build`、API `pytest`、`npm run mini:build` 与 `npm run mini:check` 全部通过；新增横向溢出检测与触控尺寸检测脚本（Playwright，360/390/1440）。
5. **真机检查**：iPhone（Safari、微信、小红书）、安卓（Chrome、微信、小红书）各 1 台；微信与小红书开发者工具编译 + 真机预览（需要真实 AppID 与 HTTPS 测试域名）。
6. **兼容回归**：用 v3 期间保存的旧分享链接清单逐个打开；旧路由跳转清单逐个访问。
7. **隐私与安全检查**：抓包确认无第三方请求、无个人信息上报；数据库检查统计表无 IP / 标识字段；限流、Origin、CSRF 用例。
8. **数据口径核对**：按 §7 构造操作序列，核对后台数值。

## 10 问题处理结论（v1.1，2026-10-18）

以下问题由技术负责人按"与设计稿意图一致、不扩大范围、可回退"的原则先行定案，并已落实到实现中。标 ★ 的项在 M1 评审时请产品负责人确认，如有不同意见可调整。

| 编号 | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 「可选更新」档位缺失 | 界面统一用「可选更新」；发布弹层与群通知补第 4 档「🔘 可选更新，按需」 |
| Q2 | 设计稿链接格式与现有路由不同 | 主路由沿用 `/software/{slug}?platform=&release=`、`/announcements/{slug}`；参数统一 `platform`，存储值 `desktop`（ADR-0004）。本期不做 `/s/`、`/n/` 短链 |
| Q3 | 反馈类型命名 | 用「链接失效」（取值 `link`） |
| Q4 | 新增「其他」分类后 9 格 | 只展示有已上架软件的分类；手机 4 列换行，电脑单行可横向滚动；「其他」图标 🗂 |
| Q5 | 同步码位数 | 10 位，去掉 0/O/1/I/L，按 5+5 显示，输入时忽略大小写、空格和短横线 |
| Q6 | 「自动检查发现新版本」待办 | 本期不做 |
| Q7 | 累计看过 / 收藏与 90 天保留 | 软件表新增 `view_count`、`favorite_count` 累计计数（不含个人信息）；按日明细仍保留 90 天 |
| Q8 | 能用率维度 | 按版本统计；软件卡片、热门取对应设备当前版本 |
| Q9 | 群通知三种格式 | 统一用 noticeText 完整模板，链接使用实际软件详情链接 |
| Q10 | 发布更新弹层字段不足 | 选择软件 + 选择设备 + 每设备入口；复杂内容进入完整编辑器 |
| Q11 | 安装教程 / FAQ 维护粒度 | 按「软件 × 设备」维护（`install_guides`、FAQ `platforms`）；某设备未填时显示软件通用步骤 `installation`。本期不做站点级通用模板 |
| Q12 | 发公告弹层字段 | 补齐重要程度、置顶、有效期、关联软件 |
| Q13 | 存量版本 advice 默认值 | 按 ADR-0003：attention → wait，其余 → optional；unavailable 不自动改 hold |
| Q14 ★ | 电脑首页 Hero 右栏标题 | 改为「最新公告」：置顶优先，不足用最新未结束公告补齐 |
| Q15 | status 可用性样式 | 按 R-DETAIL-21 实现 |
| Q16 | hold 但未指定稳定版 | 后端强制：选择「先别更新」必须指定同软件、同设备、已发布的稳定版，否则不能保存 |
| Q17 | 手机广告关闭时长 | 本次会话内不再显示该广告位 |
| Q18 ★ | 广告素材比例 | 信息流素材建议 1:1（116×116 裁切）；侧栏 300×250 居中于 336 宽容器 |
| Q19 | 推送开关与「无账号」 | 只做禁用展示，标注「规划中」 |
| Q20 | 明细保留期限 | 问题反馈明细自提交起保留 180 天后自动删除；想要的软件不自动删除（内容为软件名，不含个人信息）；同步码 30 天过期删除 |
| Q21 | 热门搜索词来源 | 后台「站点设置」可配置（≤8 个）；未配置时取近 7 天搜索统计 |
| Q22 | 点击区小于 44px | 视觉尺寸不变，用内边距 / 伪元素把点击区扩展到 ≥ 44px |
| Q23 | 「本机收藏总数」命名 | 改为「收藏总数（约）」 |
