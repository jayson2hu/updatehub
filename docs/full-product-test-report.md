## 数据恢复、健康和持续集成

原生恢复演练实际执行 PostgreSQL 17.10 的 `pg_dump --format=custom` 与 `pg_restore --no-owner --exit-on-error`，并归档、校验和独立恢复图标。恢复的 15 张表行数与内容摘要完全相同，包括 12 款软件、11 条公告、19 条帮助内容和 20 个合集成员。2 张图标字节一致；恢复库的历史管理员会话已清除，源库未改变。

恢复后的独立应用进程验证就绪、软件目录/详情、公告、指南、FAQ、合集、图标、管理员重新登录与审计读取。该演练证明原生数据恢复可行，不证明 Docker 包装脚本、容器卷、定时任务或生产切换已经通过。

`/health` 只判断进程存活；`/ready` 同时要求数据库连通且迁移 revision 与当前代码 head 一致。旧 revision、空 revision 和缺少版本表均返回 503，存活检查仍可响应。恢复脚本新增执行前校验 dump 清单，并在恢复库撤销历史会话，拒绝在线库、系统库和已有目标。

CI 新增两类真实 PostgreSQL 回归、可见 UI 浏览器任务、生产镜像服务启动与图标卷写入，以及备份/独立恢复脚本检查。容器任务限定独立 `updatehub-ci` 项目，结束仅清理其临时服务与卷；不会申请示例域名 TLS。这里仅确认配置已写入和 YAML 可解析，没有远程运行链接，不能报告“CI 已绿”。
