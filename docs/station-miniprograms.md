# 更新小站 · 微信与小红书小程序

两个原生小程序共用网站的公开接口、内容数据库、管理员发布与上传目录。访客免登录。小程序内不开放管理操作，也不打包管理员凭据或 AppSecret。

## 项目目录

| 路径 | 用途 | 导入工具 |
| --- | --- | --- |
| `apps/miniprogram` | 共用源码，以微信模板为基础 | 微信开发者工具，可直接开发 |
| `apps/miniprogram-wechat` | 构建后的微信项目，WXML / WXSS / JS | 微信开发者工具 |
| `apps/miniprogram-xhs` | 构建后的小红书项目，XHSML / CSS / JS | 小红书开发者工具 |
| `scripts/build-miniprograms.cjs` | 双端构建、模板转换、SDK适配、ES2017转译 | Node.js 22+ |

修改共用源码后运行 `npm run mini:build` 同步两个项目。不要分别修改两份生成代码。输出中的已有 AppID 在重新构建时会保留；环境变量中的 AppID 优先。数据地址通过构建配置注入，不影响后台存储。

## 本地运行

1. 按 `docs/station-operations.md` 启动现有 API（8010）与网站（3010）。
2. 在仓库根目录运行 `npm run mini:build`。
3. 微信开发者工具导入 `apps/miniprogram-wechat`，填写自己的微信 AppID；小红书开发者工具导入 `apps/miniprogram-xhs`，填写拥有开发权限的小红书 AppID。
4. 本地开发使用 `http://127.0.0.1:8010/api/v1`；仅在本地工具中关闭合法域名校验。编译后查看最新、目录、公告三栏。
5. 手机扫码预览应使用可访问的测试 HTTPS 服务，不能沿用手机上的 `127.0.0.1`。

微信游客占位 AppID 不能替代正式账号。小红书需要平台账号与对应 AppID 的开发权限。当前环境没有安装两平台开发工具，因此尚未做原生模拟器编译与扫码真机验收；交付的是原生源码、两个构建产物及已验证的共享页面逻辑。

## 已实现

- 最新更新按日期排列、软件名称/别名搜索、实际设备筛选。
- 软件目录、平台状态、软件稳定入口。
- 软件详情分别维护安卓、苹果、电视、电脑版本；版本选择与历史记录、说明、状态、获取入口同步切换。
- 主获取链接、备用入口与提取码分别展示；缺少链接和暂不可用时保持不可获取。
- 安装步骤、截图预览、FAQ展开、默认收起的历史记录。
- 公告分类、重要置顶、到期退出置顶、已结束详情、关联软件与图片。
- 原生分享路径保存当前软件、设备与版本；复制的网站详情链接同样保留选择。微信朋友圈使用对应宿主能力，小红书不调用微信专有分享菜单。
- 请求失败说明原因并可重试，下拉刷新，空搜索恢复，剪贴板失败时手动复制。
- 独立推广组件、日期与开关过滤、图片失败收起，默认广告关闭。推广目标与软件获取入口保持不同的数据来源。

## 外链处理

两端均采用「复制安卓版获取链接」「复制电视版获取链接」，说明在常用浏览器中粘贴打开。不会承诺小程序能直接跳转任意网站或唤起外部浏览器，也不依赖需要额外资质和业务域名的 `web-view`。没有真实获取链接时不展示能下载的按钮。

## 配置与部署

复制 `.env.miniprogram.example` 为 `.env.miniprogram`，填写两个公开 AppID、API与网站地址。该本地文件被忽略，不提交密钥。

```powershell
# 本地开发两个项目
npm run mini:build

# 单独更新小红书开发项目
npm run mini:build -- --target xhs

# 读取本地配置，生成体验版；两个地址都必须为真实HTTPS域名
node --env-file=.env.miniprogram scripts/build-miniprograms.cjs --env trial

# 生成正式版
node --env-file=.env.miniprogram scripts/build-miniprograms.cjs --env release
```

微信与小红书后台分别配置合法请求域名及图片下载域名；核实正式域名证书与各平台账号、类目要求。构建不会上传或发布代码。配置后分别用开发工具编译、真机检查、上传体验版，再走对应平台审核流程。

正式构建缺失HTTPS地址会直接失败，避免正式小程序误连本地数据。两端内容更新无需重新发小程序：在现有网页后台发布后，群友下拉刷新即可读取。

## 验证

`npm run mini:check` 连接当前本地 API，测试两份构建产物的页面逻辑：真实数据读取、别名搜索、设备筛选、历史版本与链接/提取码对应、分享路径、公告到期、剪贴板回退、广告开关与到期、正式配置保护。测试中的下载与广告地址仅存在于内存私有测试对象，不写入网站数据库。

这些测试不等同于平台原生编译或真机验收。仍需真实 AppID、HTTPS 服务和开发者工具来完成原生渲染、分享回流、系统字体、权限及审核检查。

## 持久化与备份

继续备份 API 使用的 SQLite 数据库与上传目录，具体路径见站点运维文档。小程序不存储另一份数据库。升级小程序不会修改或清空软件、版本、公告、图片。后续更换外观只需要调整共用样式、平台原生导航与图标。

## 小红书官方规范依据

- [小程序代码构成](https://miniapp.xiaohongshu.com/doc/DC451266)：XHSML模板、CSS样式、JSON配置、JavaScript脚本与 `xhs` 接口。
- [快速开始](https://miniapp.xiaohongshu.com/doc/DC611695)：账号、AppID开发权限、开发者工具与编译预览。
- [JS API](https://miniapp.xiaohongshu.com/doc/DC138997)：回调式接口能力与版本检测。

使用独立平台适配文件 `utils/platform.js`，小红书构建只在该文件引用 `xhs`，微信构建引用 `wx`。设备信息兼容系统信息接口；可选分享菜单与滚动等能力存在性检查，核心数据请求与获取链接不依赖分享能力。
