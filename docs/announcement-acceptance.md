# 公告中心验收标准

依据用户最新定位与 [`product-positioning.md`](product-positioning.md)。原规范第 16、17、29–31、47 节提供公告内容与人工发布要求。软件目录作为公告的背景资料和官方行动入口，保留首轮能力。

本文件是验收条件，不是通过声明。实际运行结果记录在 [`announcement-test-report.md`](announcement-test-report.md)；首轮导航平台验收保留在 `test-report.md`。

## 访客要知道什么

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| U1 | 首次打开首页 | 主标题、首屏与主要导航明确为公告中心；先展示置顶 / 最新公告，软件搜索与软件档案属于辅助入口。空库给出“暂无公告”，不显示硬编码新闻或虚构动态。 |
| U2 | 判断是否与自己有关 | 列表清楚展示公告类型、重要程度、摘要、发布时间与关联软件；可搜索并按软件、类型和重要程度筛选。筛选、结果数、分页与清除状态一致。 |
| U3 | 决定下一步行动 | 详情回答“发生了什么、影响谁、现在该做什么、为什么”；注意事项与已知问题在有内容时可见。读者不需要把软件介绍当作公告正文。 |
| U4 | 查阅可靠来源 | 更新公告提供可核对的官方来源；关联软件可进入软件档案及已启用官方入口。外链明确告知离站并使用安全的新标签行为。站点通用通知不强制关联软件。 |
| U5 | 识别演示内容 | 演示公告在列表、详情和复制文案中清楚标注；不能将 DEMO 版本、演示维护安排或演示升级建议描述成真实官方事实。演示发布不能污染真实软件的当前确认版本。 |
| U6 | 看关注内容 | 关注软件后，关注页优先展示其公开公告，仍可管理关注关系；刷新保留当前浏览器的关注。空关注与所关注软件暂无公告应可区分。清单不承诺账号同步或推送通知。 |
| U7 | 在手机阅读 | 375px / 393px 下标题、影响范围、行动、来源和操作均可阅读与点击；没有整页横向溢出。缺失、下线、服务失败有明确反馈与可用恢复入口。 |

## 管理员发布闭环

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 起草与预览 | 管理员可创建版本更新、使用提醒、维护通知；保存草稿不等于发布。预览使用当前内容，并明确标识尚未公开。 |
| A2 | 人工确认 | 草稿可先提交审核；草稿或待审核公告均须经过独立的发布操作与人工确认后公开。审核为可选整理阶段，不能靠普通保存、任意状态字段或部分 PATCH 绕过发布前校验。 |
| A3 | 必要信息完整 | 发布时标题、摘要、正文、影响范围、行动建议有效；版本更新还必须关联已公开软件、填写版本和安全的官方来源。校验针对修改后的整条公告，不能只校验本次提交字段。 |
| A4 | 修改已发布公告 | 合法修改立即体现在公开内容与复制文案；清空必填字段、移除必需软件关系或写入危险来源时，整次修改失败，原公告、软件版本及审计均保持一致。 |
| A5 | 归档与历史 | 归档后的公告保留在后台历史，但从公开列表、详情、软件关联公告、关注内容与站点地图隐藏。草稿、审核状态同样不可通过猜 slug 或 ID 公开读取。 |
| A6 | 软件上下线联动 | 已关联软件下线时，其相关公告不能继续通过公开列表或详情暴露该软件资料；站点通用通知仍可独立发布。重新发布后的可见性按实际状态恢复。 |
| A7 | 置顶与时间 | 置顶公告排在普通公告前；同组按明确的发布时间倒序，时间相同时顺序稳定。修改旧公告正文不应使其冒充刚发布的公告。 |
| A8 | 一次维护一致生效 | 公告发布 / 修改、符合条件的软件当前版本同步和审计记录在同一事务中完成；失败时不能出现公告已发布而软件版本或审计未更新的部分结果。 |
| A9 | 旧版本保护 | 在较新更新已决定当前版本后，编辑 / 重新发布较旧记录，或按真实较早官方日期补录历史公告，不能覆盖它。不能用字符串字典序判断版本大小；缺少日期时的回退顺序与归档策略必须在架构说明中明确。 |
| A10 | 复制群通知 | 管理员可复制同一条公告的文本，复制成功反馈与实际剪贴板结果相符；文案包含标题、影响 / 行动、详情地址与适当的演示标识。没有调用群聊、邮件或推送接口自动发送。 |
| A11 | 权限与审计 | 未登录不能读写后台公告；所有写操作验证 CSRF 和可信来源。创建、提交、发布、修改、归档留下可追踪审计，日志不含密码和会话 token。 |

## 本轮边界

审核状态代表管理员的内容确认流程，本轮不据此宣称具备独立审核人角色或双人审批。群通知是复制文案，不是向聊天平台发送消息。公告由人工维护，不自动识别新版本，不生成未经核实的实时新闻。

验收至少包含 API 状态与隔离用例、真实 PostgreSQL 迁移 / 事务行为、桌面与手机的发布阅读路径。Docker、HTTPS、备份恢复和正式上线继续单独验收，不能由本机公告功能通过替代。
