## 验收方式与边界

- 管理员从首页管理入口登录，通过可见导航、字段标签和按钮创建独立演示软件及公告。不得用 API 创建数据替代被测表单；API 只用于读取事实、核对结果和清理本次测试。
- 访客从首页开始，通过搜索、筛选、正文入口和导航到达目标，不直接跳到开发者预先知道的业务网址。
- 在桌面、375px 与 393px 手机宽度执行核心任务；无横向溢出只是基础，关键判断和下一步入口还必须出现在合适的位置，字号和点击区域可用。
- 自动浏览器检查后仍须查看截图，并人工复核信息层次。自动脚本只能验证可见文字和路径，不能代替真实新用户的理解测试。
- 所有测试软件、版本、发布日期和建议均标为演示，不对应真实厂商事件。测试结束归档仅本次公告、下线仅本次软件，保留审计记录。

## 本轮真实浏览器审查发现

以下为修改前在 Edge 实际交互的证据，页面坐标使用 375×812 视口，均为受控演示内容。

1. **决定与操作离得太远。** 公告的“关注相关公告”位于 y3034，“查看官方 Release”位于 y3256，之前完整展开 4 条版本历史；软件页“版本与使用建议”位于 y3018。软件官方入口通过移动端重排已位于 y433。改进方向是优先呈现当前结论、当前/历史关系和来源，把历史作为可主动回看的任务。
2. **关注写入失败没有结果。** 模拟浏览器可读但禁止写入 localStorage 后，点击关注仍为未关注且无反馈。原逻辑写入内存后继续读取未变的本地记录。改进方向是真实使用内存列表并告知保留范围，同时提供后续入口。
3. **官方入口失败断开流程。** 浏览器访问失效 `/go/…` 返回 404 裸 JSON，页面没有返回或替代路径。改进方向是公开站点提供可恢复页面，后端仍保持严格校验和原有错误状态。

另外，首页手机“我的关注”仅有 14×26 的无文字书签入口；这是发现和触控问题，不能仅凭“没有溢出”判通过。别名“蓝色代码编辑器”的公告与软件搜索、正常关注刷新保留、无结果清除筛选及旧版/当前版事实区分，在审查时均可工作。
