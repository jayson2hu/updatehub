# 更新小站：数据与扩展说明

本文记录第一版实际实现，供后续维护和接入广告功能使用。日常发布流程见 `station-operations.md`。所有公开内容由数据库读取；演示数据没有真实下载地址。

## 代码入口

| 职责 | 文件 |
| --- | --- |
| 站点数据模型 | `apps/api/app/models/station.py` |
| 字段、链接、图片路径校验 | `apps/api/app/schemas/station.py` |
| 读写、发布、权限之外的业务校验、上传 | `apps/api/app/services/station.py` |
| 前台与后台 API 路由 | `apps/api/app/api/station.py` |
| 演示数据 | `apps/api/app/seed_station.py` |
| 集成测试 | `apps/api/tests/test_station.py` |
| 数据库迁移 | `apps/api/migrations/versions/8e52286e943a_station_community_updates.py` |

该模块沿用项目的 FastAPI、SQLAlchemy、Alembic 和管理员登录机制。新增表均以 `station_` 开头，迁移不会删除或覆盖旧目录、旧公告、管理员或审计记录。前端通过 Next.js 同源代理访问 `/api/*` 与 `/uploads/*`，浏览器无需直接连接另一个端口。

## 数据结构

| 实体 | 数据表 | 作用 |
| --- | --- | --- |
| 软件 | `station_software` | 固定分享标识、名称、别名、设备、状态、图标、安装步骤、问答、截图、上下架和示例标记 |
| 平台版本 | `station_release` | 所属软件与设备、版本号、说明、独立状态、安装提醒、草稿/发布、发布时间 |
| 获取入口 | `station_release_link` | 所属版本、来源名、HTTP(S) 地址、提取码、主要入口与顺序 |
| 公告 | `station_announcement` | 分类、重要程度、正文、配图、链接、置顶、到期与发布状态 |
| 公告关联 | `station_announcement_software` | 一条公告关联多款软件，数据库外键保证关联有效 |
| 站点设置 | `station_settings` | 站名、简介、使用说明、广告总开关；固定记录 `site` |
| 推广 | `station_promotion` | 独立的标题、正文、封面、目标链接、投放时间与位置；第一版预留 |

安装步骤、问答、图片列表等结构化内容使用 JSON 字段。获取链接使用独立关系表，完全不依赖推广表。公告正文和更新说明采用纯文本段落，图片和链接分别保存并校验，前端不把管理员输入作为 HTML 执行。

管理员继续使用 `admin_user` 和 `admin_session`；每次站点内容修改与上传写入已有 `audit_log`。密码用 Argon2 哈希保存。浏览器会话是随机不透明令牌，数据库只保存令牌哈希，不需要额外设置 `SECRET_KEY`。

## API 契约

公共前缀是 `/api/v1/station`，访客无需登录。

| 方法与路径 | 结果 |
| --- | --- |
| `GET /data` | `{settings, software, releases, announcements, promotions}`；仅公开软件、公开版本和已发布公告；广告关闭时 promotions 为空 |
| `GET /software/{slug}` | `{software, releases, announcements}`；版本按发布时间降序，含历史公开版本；关联公告含已结束记录 |
| `GET /announcements/{slug}` | 单条已发布公告；到期仍可访问，撤回返回 404 |
| `GET /promo/{slug}` | 已上线推广；广告总开关关闭或记录下线时返回 404，已结束活动详情可以保留访问 |

后台前缀是 `/api/v1/admin/station`。

| 方法与路径 | 结果 |
| --- | --- |
| `GET /data` | 全部站点内容，包括草稿；需要管理员会话 |
| `POST /software`、`PATCH /software/{id}` | 新建/修改软件；成功返回完整软件；新建状态码 201 |
| `POST /releases`、`PATCH /releases/{id}` | 新建/修改版本；用 `published` 保存草稿或发布；新建状态码 201 |
| `POST /announcements`、`PATCH /announcements/{id}` | 新建/修改公告；`published: false` 撤回；新建状态码 201 |
| `PATCH /settings` | 修改站点设置；未提供的字段保留原值 |
| `POST /uploads` | `multipart/form-data` 的 `file` 字段，成功返回 `201 {"url":"/uploads/…png"}` |

写操作要求登录会话、正确的 `X-CSRF-Token` 与允许的来源；无会话返回 401，CSRF/跨站校验失败返回 403。登录、当前会话、退出仍使用 `/api/v1/admin/auth/login`、`/me`、`/logout`。生产 Cookie 带 `Secure`，始终带 `HttpOnly` 和 `SameSite=Strict`；后台响应使用 `Cache-Control: no-store`。

`PATCH` 支持只提交需要修改的字段。`id`、`created_at`、`expired` 和 `effective_pinned` 等只读字段不能回写。表单字段错误返回 422 和中文操作说明；分享标识重复返回 409。未知字段被拒绝。接口原子提交，失败不会部分修改旧内容。

平台值为 `android`、`ios`、`tv`、`desktop`。使用状态为 `normal`、`attention`、`unavailable`；需结合 `status_reason` 呈现文字。公告分类为 `group`、`usage`、`maintenance`，重要程度为 `normal`、`important`、`urgent`。

## 发布与固定链接

- 软件与公告的 `slug` 在创建后不可修改。可以调整名称、别名和内容；群里已分享的固定入口保持有效。
- 各平台分别维护版本与获取入口，版本所属的软件和平台不能在编辑时改变。已有任何版本记录的平台不能从软件的支持列表移除；可把对应版本设为暂不可用并填写原因。
- 发布新版本创建新的版本记录，不覆盖旧记录。旧版本保留在历史中。相同平台以公开版本的 `published_at` 降序确定当前版本。
- 第一次发布草稿时自动填入当前时间。普通编辑保留发布时间；显式提交 `published_at` 时以提交值为准。服务端统一输出带时区的 UTC 时间，界面按中国时区展示日期。
- 沿用上一版内容创建新版本时，复制字段和链接内容，并移除旧版本的 `id`、`created_at`、`published_at` 和链接内部的 `id`。旧入口 ID 不能关联到新版本。
- 软件下架后，它的所有版本均从公共接口隐藏。公告撤回后，列表、关联软件页面和原分享入口均不可公开访问。
- 公告每次读取时计算 `expired` 与 `effective_pinned`。到期无需定时任务即可退出置顶，历史详情仍能显示「已结束」。数据库保留原 `pinned`，便于管理员理解历史设置。

## 图片与输入边界

只接受真正能解码的 PNG、JPEG、WebP。上传体最大 5 MB；单边不得超过 8000 像素，总像素不超过 2400 万。图片按比例缩小到最长边 2400 像素，修正 EXIF 方向后仅重新保存像素为 PNG，去掉元数据。SVG、伪装文件和异常图片被拒绝。

上传文件名由服务端随机生成，不使用原文件名，统一落到 `UPLOAD_DIR`。软件图标、截图、公告配图只接受上传接口返回的本站路径。持久化目录应固定并可写，重启时继续挂载同一目录。新增图片暂不自动清理，避免误删仍被历史记录引用的文件；未来可增加引用检查后的垃圾清理。

外部获取地址和公告链接只允许完整的 HTTP(S) URL，不接受脚本协议、控制字符、反斜线或带账号密码的地址。系统不会主动请求这些下载地址。如果未来增加链接有效性探测，需要另外实现 DNS/IP、重定向和请求超时校验，不能把现有存储校验当成服务端网络访问许可。

## 广告扩展接入点

广告总开关为数据库设置 `ads_enabled`，默认关闭。第一版没有广告管理表单、投放统计、自动跳转或第三方广告 SDK；推广记录是未来模块的稳定数据接口。

`station_promotion.placements` 采用以下固定值：

| 值 | 展示位置 |
| --- | --- |
| `home_feed` | 首页列表中部；不能挤占重要公告与首条更新 |
| `detail_body` | 软件详情正文内 |
| `desktop_sidebar` | 桌面侧栏 |

前端对应独立推广组件与 `/promo/{slug}` 页面。关闭、未上线、尚未开始或已到期的投放不出现在公共聚合结果里；没有广告时组件自然收起。素材使用固定比例，独立延迟加载，显示「推广」标签。推广按钮与软件获取操作分开。

活动详情可以使用 `starts_at`、`ends_at` 显示未开始、进行中或已结束；已结束仍发布的活动保留详情链接，下线记录返回 404。无效推广配置会在聚合接口中被单独跳过，不会导致软件列表、公告或版本链接读取失败。

未来管理模块应复用当前管理员认证与 CSRF，先校验素材、目标地址、有效时间、位置枚举，再写入推广表。统一开关应同时包住未来第三方广告脚本的加载。若增加下载前中转页，应新建独立流程并保存软件 ID、平台和版本 ID，明确显示「继续获取软件」；不得把推广目标替换进获取入口表。

## 迁移、演示与部署边界

在 API 目录执行 `python -m alembic upgrade head`，随后按需执行 `python -m app.cli seed-station`。本次迁移版本为 `8e52286e943a`，父版本为 `7b50d52a94fc`。演示命令创建 6 款虚构软件、11 条版本和 4 条公告；再次执行不会覆盖同标识的现有内容。示例全部标记为示例，获取链接留空。

`GET /api/v1/ready` 既验证数据库可用，也验证迁移版本与应用一致；`/health` 只表示进程可响应。发布代码与执行迁移应作为同一次部署进行。

本地可用 SQLite，`DATABASE_URL` 指向固定数据库文件。当前项目生产配置明确要求 PostgreSQL 与 HTTPS：不要通过关闭生产环境标志来绕过安全校验。上传目录和数据库必须使用持久化磁盘、容器卷或等价方案；临时文件系统、无持久卷的无服务器环境不适合当前上传实现。

当前登录限速器存于进程内，建议单 API worker；多实例部署前替换为共享限速存储，并为上传使用共享存储或对象存储。聚合接口面向小型社群内容量；规模增大后可以保留详情接口，并把列表搜索和分页下沉到数据库。

备份必须同时包含数据库与 `UPLOAD_DIR`，并保留同一时间点的配对副本。SQLite 可停服复制或使用 SQLite 在线备份功能；PostgreSQL 使用 `pg_dump` 等一致性备份方式。恢复到独立环境后执行就绪检查，并抽查软件、公告、平台版本和上传图片，再切换正式流量。不要把数据库密码、管理员初始密码或会话令牌写入文档和版本控制。
